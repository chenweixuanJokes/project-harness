# 从旧版本升级

面向已安装旧版 Project Harness（PH）的用户。官方仓库已由 `ph-init` 更名为 `project-harness`，旧地址 `https://github.com/chenweixuanJokes/ph-init` 经 GitHub 自动跳转指向新仓库，本页说明各类旧状态如何升级到当前正式版。

先说结论：**改名本身不需要任何迁移动作。**入口和技能名不随仓库名变化：入口仍是 `ph-init`，技能仍是 `ph-*`，用户级安装路径仍是 `~/.agents/skills/ph-init`。已装项目记录里的旧仓库地址（项目清单、下载回执、升级状态中的 `repository` 字段）是 1.x 的兼容设计，不需要也不应该手工改成新地址——工具校验的就是这个固定值。

## 项目已是 1.1.8

在项目对话里直接说：

> 用 ph-init 升级 PH，保留项目自己的规则和文档，先给我看差异。

助手会下载最新正式版并给出完整升级差异，确认后才写入。不需要换入口、重装或移动任何目录；旧地址下载经自动跳转仍然可用。所有 PH 技能（含升级）都需要点名才会执行。

## 项目是 1.1.7 及更早

从 1.1.8 起 PH 只保留一个版本号，旧安装工具无法读取新版发行包，首次升级要先做一次性入口切换。把下面的话交给助手：

> 用 ph-init 从官方仓库的 v1.1.8 标签获取新版工具，放到项目之外的新目录，不覆盖已有入口。先用它准备 v1.1.8，再用新版工具准备最新正式版，检查这个项目的完整升级差异，确认后再写入。

升级完成后，使用项目内更新过的入口。用户级的旧副本没有被覆盖，若客户端仍优先加载它，需要调整客户端的技能入口。

## 手动克隆过旧分发仓

例如 `~/.agents/skills/ph-init` 是从旧地址 clone 的：克隆内容仍然可用，`git pull` 会经跳转继续工作。想改用新地址时执行：

```bash
git -C ~/.agents/skills/ph-init remote set-url origin https://github.com/chenweixuanJokes/project-harness.git
```

不要删除重装，也不要在旧名 `ph-init` 下新建仓库——那会切断自动跳转，影响所有尚未升级的旧版用户。
