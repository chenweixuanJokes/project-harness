## 数据约定

`files` 相对本 `evals/` 目录，非空时复制到隔离临时目录后执行。`setup` 是评估会话前提，应由运行者提供；不能把它当真实项目授权。`assertions` 检查输出和执行轨迹，不能只搜“未授权”“通过”等词；使用 skill-creator 其他工具时按实际 schema 转换。

每个场景记录：技能版本、运行模型/宿主、输入与 setup、输出文件、调用轨迹、实际副作用、断言结果及证据。禁止把模拟用户回答计为真实用户验收。

## 如何评估

1. **结构检查**：元数据、链接、JSON、夹具存在。只能证明材料可读。
2. **夹具检查**：源夹具的既有测试应通过，空结果复现应失败；临时副本最小修复及新增测试后应通过。这证明测试材料能区分目标缺陷，不证明模型会遵守技能。
3. **主 Agent 走读**：逐场景核对规则能否给出一致动作和结束状态。自审有上下文偏差，不计独立通过率。
4. **独立行为评估**：在新的隔离会话中分别加载旧版/新版同一场景，检查实际产物与轨迹，重复运行观察稳定性；触发与任务完成分开评分。用户本轮仅允许研究委派，因此这一项未执行。

涉及发布、审批、用户反馈和 Git 的案例使用隔离测试环境或事件夹具；未搭建对应环境就标未执行，不在真实项目制造副作用。真实宿主调用门禁、审批、技能资源加载及 PH worktree 生命周期仍需单独集成测试。

场景已包含每阶段的讨论性负例；这不是全面触发准确率测试集。后续量化比较应加入更多自然表达及近似负例，并用相同模型、权限和输入，不能用作者当前会话的理解代替技能本身。
