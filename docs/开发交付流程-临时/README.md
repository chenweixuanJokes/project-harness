# 四阶段开发技能套件（临时草案）

本目录用于审阅和验证，尚未安装，不改变当前 PH 规则。本轮在用户确认的当前新稿基础上整合，不把新稿已有改进冒充本轮新增。

## 四个入口

- [ph-prepare](skills/ph-prepare/SKILL.md)：核实现状，选择简版或标准版规格，明确任务和验证方法。
- [ph-implement](skills/ph-implement/SKILL.md)：按有效规格完成实现、测试、文档与评审。
- [ph-verify](skills/ph-verify/SKILL.md)：通过真实入口取得用户反馈，组织受影响点复验。
- [ph-deliver](skills/ph-deliver/SKILL.md)：按授权交到本地、PR、目标分支或发布环境，确认最终事实。

点名单阶段就在交接处结束。完整流程须有用户请求且项目允许衔接；它不自动授予提交、推送、合并、发布或清理权限。

## 怎样选择流程

局部、明确、低风险任务使用简版规格，写清目标、保留行为、位置和检查。复杂或高后果任务使用标准方案；宿主和项目要求的正式审批始终优先。准备请求不会自动变成实施请求。

沿用一份已有任务记录，不强制造 spec、plan、tasks 三份文件。没有 PH、子代理或 worktree 也可以执行普通任务；需要 PH 特定能力时才读取条件适配。主 Agent 负责用户交互、事实记录和最终判断。

## 资源布局

各技能正文按实际操作安排必要边界，专项资料位于各自 `references/`：

- 准备：记录模板、原型试验、评审选择、工作区适配。
- 实现：委派与评审方法。
- 验收：真实入口与复验方法。
- 交付：工作区适配、条件依赖与复验方法。

单个技能目录包含本阶段所需指导，不依赖兄弟共享目录。少量通用边界有意在入口简述；修改边界时应同时检查四个入口。目录自包含不等于已验证各宿主安装、触发或沙箱兼容。

## 发行边界

本目录不提供安装器，不替代正式 PH 技能。正式接入仍需确认旧入口、记录兼容和调用政策，并完成版本、迁移、完整回归及历史升级矩阵。本轮不修改 scaffold、release.json 或安装升级运行时，不提交、推送、发布。
