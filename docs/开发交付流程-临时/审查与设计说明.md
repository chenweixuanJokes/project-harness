# 四阶段技能审查与重构说明

> 本文保留此前设计。当前重构见 [本轮调研与重构](本轮调研与重构.md)：已将整块通用边界改为步骤内说明，并按阶段收窄重复参考材料。

## 此前结论

2026-09-18 整合说明：写入前发现目录已更新，用户明确选择以当前新稿为基线继续。以下简版规格、行为示例、发布恢复等改进已存在于该基线；本轮新增的是自包含资源、入口就地边界、二次核验更正及可追溯演练。原稿快照已保留，不能把基线改进全部算作本轮工作。

旧稿不是缺少限制，而是缺少帮助执行者作正确选择的方法。四阶段本身合理：准备确定行为和验证，实现取得技术证据，验收取得用户反馈，交付核实最终位置。本轮保留四个名称和阶段边界，重写执行方法，取消强制 worktree 与固定规格负担。

修改范围仅为此临时套件和配套审阅材料，不安装、不改正式 PH 规则、不提交或发布。重构前完整副本已保存到系统临时目录；旧验证记录继续保留为历史，不当作新稿证据。

## 逐项对照

| 原稿问题 | 本轮改法 | 依据与取舍 |
| --- | --- | --- |
| 每项任务都要求正式计划和 PH task worktree；准备完成混同于工作区创建完成 | 简版/标准版规格，遵守项目实际审批；当前工作区可用就沿用，隔离能力按需加载 | Claude Code 规划/worktree 文档、Kiro Quick Spec。轻量是减少无价值产物，不豁免强制审批 |
| 规格只有“目标、范围、标准”等字段名，未教会如何写出可验证行为 | 写条件、操作、结果；明确非目标、失败/边界、必须保持的行为；增加具体示例 | Kiro 行为需求和缺陷结构、Google 测试实践；不强制所有领域采用同一形式语言 |
| 计划内容、任务和批准状态容易混成一项 | 有效规格与操作授权分开，简版承接明确修改请求，标准版记录真实审批依据 | 方案确认不能代替外部操作权限，仍以宿主规则为准 |
| 技能短，但正文偏向状态核对，缺少实现中的决策方法 | 区分缺陷、新行为、重构的验证起点；失败先区分测试/环境/产品原因；再做最小修改 | 可运行验证与反馈回路，而不是“不断试到通过” |
| 评审依赖泛化，容易产生固定代理队列或自审冒充独立评审 | 明确按风险选择，发现需触发条件、后果和证据；允许零发现；强制独立评审缺失仍阻断 | 多代理研究经验不等于编码普适收益，评审也是可能出错的信号 |
| 主记录看似完整，小修复却要填大量字段 | 一份记录的两种详细程度，保留稳定标准编号和变更影响 | 渐进披露用于内容和流程；不创建竞争的 spec/plan/tasks |
| PH 固定依赖使非 Git/非 PH 任务也受阻 | dependencies 改为条件能力发现清单，Git/PH 适配只在实际使用时要求 | 客户端、模型 API、技能是不同层；保留真实 PH 调用门禁 |
| 兄弟共享目录使单技能不能自包含 | 必需边界就地放在入口，专项资料放入各自 references | 少量内容重复换取独立可读；不复制四份完整契约，不引入构建系统 |
| 交付只区分目标，未充分说明发布失败和重试后果 | 核实发布判据、恢复能力、非幂等结果未知、CI 等待及已部署失败状态 | 外部动作结果须查询确认；恢复授权独立，不自动回滚 |
| 验收容易被预检或无人响应替代 | 真实入口、角色、成果和反馈绑定；跳过仍未验收，纯内部任务用已有不适用依据 | 保留旧稿最有价值的真实用户验收边界 |
| 旧 eval 多为空输入、提示透露规则、预期与强制 worktree 绑定 | 修正过时预期，增加自然提示与可运行夹具；区分静态、走读、夹具与模型评估 | 验证实际行为和副作用，而非只数关键词或行数 |

## 架构选择

### 四个入口，不增加第五个总控

单阶段执行到交接；完整流程只有用户明确请求且项目允许时衔接。当前正式 PH 仍实行逐技能显式调用，本临时套件不改掉这条规则，也不通过内部脚本绕过。

### 各入口自包含，专项资源按需加载

四个正文就地说明权限、证据、恢复和阶段结束边界，不再先加载共享 contract。record 归准备，worker 归实现，verification 归验收与交付；评审和工作区材料在实际需要的技能内保留。工作区材料内的条件清单由各入口直接列出读取条件，避免隐藏依赖。

这是可维护性与便携性的取舍：重复的少量边界修改时同时核对，静态检查保证引用不逃出本技能目录；不声称已经通过真实宿主安装测试。原共享目录已迁入废纸篓，基线另存系统临时目录。

### 规格用于澄清，不试图提前编写另一份代码

目标和非目标先明确，标准可观察，实现可以在范围内调整。关键需求变化才更新批准范围；普通实现细节不机械重启准备。历史记录保留决定，当前产品文档维护事实，避免规格与代码永久双写而无人负责。

### 保留高价值约束，不追求否定词归零

旧验证曾扫描“不要/禁止”等词并以零出现作为风格结果。本轮取消这个目标：减少重复说教，但必要边界可以直接写“不能”。质量由可执行性、范围和证据判断，不由语气词计数判断。

### 不将提示词当安全系统

仅使用通用 name/description/compatibility，不假定某个 Claude 字段能约束所有客户端。共享文件的单写入者和主 Agent 交互是本套件组织方式；真实权限、沙箱和工具限制由宿主落实。没有额外开发 hook、运行时框架或安装器。

## 调研与验证边界

来源及采用理由见 [二次调研依据](调研依据.md)。覆盖 OpenAI、Anthropic、Google、DeepSeek、智谱、Kimi，以及 GitHub/AWS 的 SDD 和独立反向案例；证据不足的资料明示未核实，未当硬性依据。

用户仅允许研究派子代理，因此本地审阅、所有修改和场景检查由主 Agent 亲自执行，没有通过另一模型做基线对照或独立评审。实际检查见 [验证记录](验证记录.md)，评估执行方法见 [evals/README.md](evals/README.md)。静态正确和夹具跑通不等于技能在干净会话中的行为可靠。
