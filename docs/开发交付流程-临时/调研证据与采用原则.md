# 调研证据与采用原则

检索日期：2026-09-17。三组公网调研由 web-explore 执行；本地技能审阅、取舍、写入和检查由主 Agent 完成。下列来源由调研者读取公开正文；访问失败与仅搜索摘要的材料单列，不作为已核实依据。本文保留影响设计的证据，不把平台功能列表复制进运行技能。

## 1. 如何使用这些资料

区分三类：**开放规范**规定文件格式；**厂商文档/经验**说明特定工具或团队如何工作；**本套件选择**是依据这些材料作的工程取舍，仍需行为评估。官方来源不等于通用行业标准，产品在线文档可能变化，日期未知的记为未标注。

本轮未证明重构使成功率、速度或成本改善。也未把搜索广度说成穷尽全网。模型 API、客户端技能加载和代理运行时是不同层：API 支持工具调用，不代表客户端会发现技能或继承权限。

### 反向证据也要看

- [Scott Logic 的 Spec Kit 实践](https://blog.scottlogic.com/2025/11/26/putting-spec-kit-through-its-paces-radical-idea-or-reinvented-waterfall.html)（2025-11-26）报告规格膨胀、评审成本和仍有实现缺陷。这是单案例，不证明 SDD 普遍无效，但足以反对“更多文档必然更好”。

- [METR 早期 2025 工具实验](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)（2025-07-10）在特定资深开源维护者样本中观察到使用 AI 更慢。不能外推到所有开发或当前模型；采用的是“效率需实测，不能凭感觉声称提升”的方法论。

## 6. 评估而非自我证明

[Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)（2026-01-09）讨论任务、轨迹、结果与多类评分器；[官方 skill-creator](https://raw.githubusercontent.com/anthropics/skills/refs/heads/main/skills/skill-creator/SKILL.md)（未标注）采用 with-skill/baseline、断言和人工复核；[OpenAI Tracing](https://openai.github.io/openai-agents-python/tracing/)（未标注）说明工具、模型和移交的可追溯执行记录。

因此本轮把结构校验、主 Agent 场景走读、隔离夹具命令测试、独立模型行为评估分开报告。用户只允许研究派子代理，本轮不借评估名义启动第二个模型。新增场景与夹具供后续干净会话评估，不能把场景数量写成已通过行为用例数。
