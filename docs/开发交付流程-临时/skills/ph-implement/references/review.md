# 检查代码改动

在本任务写入结束后检查实际差异、新增文件、调用方和测试，不只看实现者总结。

## 检查重点

- 行为符合约定，正常、边界和错误路径有对应检查。
- 权限、数据和公开接口没有意外变化。
- 新测试能抓住目标缺陷，没有删除、跳过或削弱原有检查。
- 说明与实际用法一致，没有无需求依据的扩展。

## 选择评审方式

项目强制要求优先。普通局部修改可自审；安全边界、数据迁移和重要兼容变化安排实现者以外的执行者或人类评审。用户禁止委派时由主 Agent 自审；独立评审是强制项但尚未取得时，仍然受阻。

评审者只需目标、非目标、行为标准、实际差异、对应版本和检查结果，可以只读调查调用方。不要预设必须找到几个问题，另一 Agent 的身份也不保证结论正确。

## 处理发现

每条发现写文件与位置、触发输入、实际后果、证据和建议。未证实的疑点列为待查，风格偏好单列。

主 Agent 核实成立的问题，修复后重跑相同触发输入及相关回归；不成立的保留反证。涉及范围或兼容改变时先取得决定，不能用评审建议扩大授权。重要修复应复审。

报告实际检查范围、已处理问题、剩余阻断及限制。自审称自审，没有发现不等于保证没有缺陷。
