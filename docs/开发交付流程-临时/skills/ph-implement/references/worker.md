# 委派实现任务

适合委派的是能单独检查的成果、专业工具任务，或会产生大量中间资料的调查。紧耦合修改由同一执行者完成代码和测试，不按编码、测试、修复拆成固定队列。遵守用户与宿主的委派要求；没有代理能力可以串行完成，强制独立评审另行处理。

## 派发前写清

- 目标：交付什么，对应哪些标准，哪些不做。
- 输入：已确定的方案、必要事实和实际文件路径。
- 范围：工作目录、只读或可写文件、共享资源与操作权限。
- 完成条件：检查入口、预期结果、停止条件和已有预算。
- 回传：结论、改动位置、实际检查、证据及未完成项。

不传整段会话、秘密或无关日志，不假定执行者继承主会话或能再次委派。只读调查不授予写入权限；实现授权不附带提交、发布或直接询问用户的权限。主 Agent 负责用户交互和共同任务记录。

## 安排并行

接口和前置成果已确定才能并行。共享文件、锁文件、生成物或数据库由一个执行者处理，或串行安排。worktree 不能隔离端口、数据库和外部服务。

执行者发现方案与现场冲突时暂停相关操作并回报；预算耗尽保留现场，不换人重置预算。用户改变目标时，主 Agent 停止受影响工作并核实已产生的修改。

## 接收结果

执行者区分完成、部分完成与受阻，回传实际命令、输入、环境和结果，未运行项说明原因。“测试全过”或“请求已受理”不足以证明完成。

主 Agent 检查决定性差异与证据，按风险补必要验证，不重做全部调查。缺陷返修，事实缺口补查，范围变化先取得决定；更新任务记录后再安排依赖任务。最终交接前等待或停止相关执行者，并检查结果。
