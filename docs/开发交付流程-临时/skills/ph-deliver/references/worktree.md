# Git 与工作区

执行 Git 交付或清理前读取。使用项目已有流程，不另建分支、提交或合并协议。

## 操作前

核实仓库、当前分支、源与目标，以及暂存、未暂存、新增文件和相关 ignored 资源。区分本任务与原有改动，未知内容保留。提交只包含获准范围，不用全量暂存代替核对。

逐项核实提交、推送、PR、合并与清理权限。已有明确授权不重问；没有 Git 的本地文件交付无需补造仓库。

## PH 工作区

[条件清单](dependencies.json) 的路径相对目标项目根目录。交付或恢复 PH task worktree 时，先满足 `ph-worktree-exit` 的调用要求，再使用它的验证、提交、合并与最终检查流程。

冲突或登记不一致时先诊断；修复后再次交付沿用该技能的 redeliver 方法。WIP 确认、验证配置与安全筛查也沿用原能力，不在这里复制参数和问句。

只调用 ph-deliver 不等于已调用其他技能；缺调用权限就停在该动作前，不直接执行内部脚本。没有 PH 时使用项目现有 Git 方法。

## 中断与清理

失败或超时后先查历史、PR 和操作回执，确认动作是否已发生，避免重复提交或合并。项目强制检查与任务检查分别满足；固定命令列表为空不是免检依据。

合并后检查最终内容。失败时保留现场，如实报告；后续修复、回滚和发布各按已有权限处理。

清理前核对资源归属、实际内容、交付条件及独立授权。worktree 不隔离外部服务，不能仅凭目录名认领端口或数据库。未知文件、ignored 资源和用户成果不能因“临时”标签被删除。使用项目允许的清理方式；保留工作区是有效结束状态。
