# 检查结果与复验

交付前判断已有结果是否仍能证明当前成果，交付后检查实际到达的位置。

## 哪些结果可以复用

核对标准、代码或文件内容、依赖、配置、实际构建、环境与角色。commit 相同不代表未提交内容没变；任务摘要或快照须包含相关未跟踪文件。

只有过程记录变化时，无需重跑产品测试。产品或环境变化时，列出受影响标准，更新相应检查；不依据文件路径未重叠就认定行为不受影响。影响不清时扩大相关检查。

## 最终位置要检查什么

- 本地：文件可取得并打开，命令或服务入口可用。
- PR：仓库、目标分支、提交和 CI 状态正确；未合并就保留待合并状态。
- 合并：目标分支包含成果，集成检查通过。
- 发布：实际版本与目标环境匹配，健康和必要功能检查通过；异步受理不等于部署完成。

启动、重启或安装依赖仍需已有权限，只读会话不能为准备环境写入。命令退出零不能代替功能结果，提供地址也不等于用户能访问。

## 何时重做用户验收

修复、集成或环境变化影响用户标准时，先补技术检查，待成果稳定后取得对应用户反馈。保留未受影响的有效反馈。

记录实际入口、角色、输入、版本、反馈和证据位置。用户看到的版本与当前版本不同，旧回答保留为历史，不能直接算当前通过。Agent 预检不代替用户回答，未回答或跳过仍是未验收。

只请求交付时交接必要复验；完整流程在项目允许且已授权时才读取验收技能。回执分别说明已发生操作与验证结果，不能把“已部署但检查失败”改写成未部署或交付成功。
