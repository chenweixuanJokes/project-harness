# 准备验收入口

先读项目启动说明和实际脚本，优先使用已有环境。启动、重启、安装依赖或公开服务前核实权限；只读会话只查事实，记录待准备项。

## 按成果选择入口

| 成果 | 提供给用户的内容 |
| --- | --- |
| 网页 | 实际功能页、正常导航、账号角色和操作输入 |
| CLI | 可复制命令、输入及运行环境 |
| 接口或库 | 对应版本的最小调用、参数、预期返回与副作用 |
| 桌面程序 | 实际程序位置、版本和操作步骤 |
| 文件 | 可取得的文件、打开方法与核对内容 |

核对实际构建和用户可达性。多角色或多端要求分别安排；下载核对实际文件，异步任务按约定判据等待完成。

“已提供地址”“打开请求已受理”和“用户已看到页面”是不同事实，按实际发生的记录。模拟数据、原型和 Agent 预检明确标记，不当正式验收。

## 保存与复验

每条反馈对应标准、角色、环境、版本、输入和预期，保存用户原话或忠实转述。链接和日志去除秘密信息。

反馈与预检冲突时，保留两份证据，先核对版本、角色、环境与输入。代码或配置修复期间暂停受影响验收；稳定后先补技术检查，再询问对应用户标准，未受影响结果继续沿用。

工具故障、环境不可用和用户未操作分别记录原因及恢复条件，不把任何一种直接写成产品失败。
