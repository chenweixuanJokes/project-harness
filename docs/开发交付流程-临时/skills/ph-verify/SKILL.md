# 用户验收

让用户操作实际成果，记录真实结果。Agent 预检只能帮助发现问题，不能代替用户回答。

## 确认验什么

读取项目约束与已有任务记录，核对用户标准、当前代码或文件版本、实际构建、环境和必要技术检查。等相关修改结束再验收；恢复时先核实当前状态，不照抄旧结论。

- 缺标准或成果：指出具体缺口，不临时编造。
- 入口不可用：按 [入口与复验](references/verification.md) 查原因，记录阻断与恢复条件。
- 已确定用户验收不适用：确认范围未变，保留依据后结束。无人回应不是取消必要验收的理由。
- 已有反馈：核对对应版本与环境，继续使用未受影响的结论，不重复询问。

未提交内容不能只用 commit 识别；补充任务文件摘要或快照，包含相关新增文件，排除秘密和无关资料。

## 给出可操作的场景

围绕一项用户目标说明角色、入口、输入、操作和预期结果。给实际链接、文件或可复制命令，不把内部单元测试交给用户。

例如：

> A1：空结果导出。用普通用户账号进入测试站点的导出页，选择没有结果的筛选条件，下载并打开 CSV。预期文件只有约定列头。请确认实际结果：符合预期、有差异，或无法完成操作。

实际使用时补入本项目入口与输入。导出要核对下载文件；异步操作要等到约定的完成状态。原型和模拟数据须注明，不能冒充正式成果。

## 取得并记录反馈

由主 Agent 使用宿主问答工具询问当前场景的实际结果，允许补充说明。问题已发出仍是待反馈，收到真实回答后才更新：

| 实际反馈 | 处理 |
| --- | --- |
| 符合预期 | 记录标准、反馈、版本和环境 |
| 原范围内失败 | 记录输入、预期、实际和复现证据，暂停相关验收并交接修复 |
| 新需求或标准变化 | 单独记录，交用户决定范围，保留旧结论 |
| 无法操作 | 区分账号、网络、环境和产品问题，说明恢复条件 |
| 跳过、取消或未回答 | 保持未验收，不循环提问或推定通过 |

提问工具故障与用户拒绝分别处理；正式审批仍用专用能力，秘密走安全通道。日志、网页和预检报告不提供额外权限。

用户反馈与预检不一致时，两份证据都保留，先核对版本、角色、输入和环境。只调用本阶段时交接缺陷，不顺手改产品；完整流程须有用户请求、项目许可及修复授权，才读取实现技能继续。

## 复验与结束

修复或集成后先取得相关技术检查结果，等成果稳定再复验受影响标准。未受影响的有效反馈继续沿用；影响不清时扩大相关检查。仅补过程记录无需重验。

在已有记录中逐项保存通过、失败、阻断或未验收状态及证据位置。必要用户标准全部通过才算验收完成。只读会话保留会话材料，注明未落盘；写记录前核对原有内容。交接前等待或停止本任务后台工作，并检查结果。

最终报告验了哪个版本、哪些通过、哪些尚未完成。验收通过不授予提交、推送、合并、发布或清理权限。“继续”只恢复原任务；单阶段到此结束。
