# 项目化内容验收

使用时机：新项目初始化、存量项目接入、升级与同版本补全时读取。

## 三种项目

- 存量非 PH 项目：先盘点代码、配置、锁文件、测试、旧规则及未提交内容；保全原件后生成仓外合并候选，不先安装空模板覆盖旧文。按终态基础树逐篇承接现行内容。
- 已安装 PH：按迁移链合并，基础树缺项全部补齐，旧有效专题可以作为新增文件保留。自动完成无冲突且已授权的动作；遇到无法核实的矛盾只阻断受影响部分。归档不等于完成迁移。
- 新项目：从基础需求和已有选型制定目录、契约、编码、安全与测试约定；选型缺失但可合理决定时采用简单、受支持的方案，并查阅对应版本官方资料。计划命令明确标记尚未实现或执行，不捏造代码、测试成功或负责人。需求缺失影响架构时记录阻断，不能将未知当不适用。

没有某一端仍保留该端全部基础文档，正文说明不适用及依据，移除该端无意义的占位表。共同规则可复用，但每篇适用结论应针对本项目。

## 报告与脚本

`.agents/init-report.md` 保留可读的覆盖结论。在 `.agents/project-harness/init-report.json` 记录同一次核验的文件证据，不另行维护第二套事实。说明文字确实需要展示填写语法时，在该行标 `<!-- ph:placeholder-example -->`；不得用此标记豁免实际待填内容：

```json
{
  "format": "ph.content/1",
  "project_kind": "existing",
  "documents": {
    "前端规范/技术规范.md": {
      "status": "verified",
      "sha256": "实际正文的 SHA256",
      "evidence": "核验过的代码、配置、旧规则或需求位置",
      "reason": "采用这些约定的项目依据",
      "semantic_review": true
    }
  }
}
```

`project_kind` 为 `existing`、`new` 或 `upgrade`。每份非模板基础规范及新增规范专题必须有一行；`status` 为 `verified`（已核实）、`adopted`（按需求采用的约定）或 `not_applicable`（明确不适用）。有冲突或关键信息待核实时不可使用这些完成状态。`semantic_review` 仅在主代理读过并核对正文后填 true；哈希只证明核对的是哪一版，不能证明事实正确。

用同一发行根或目标已安装内核执行：

```text
python3 <ph-init>/scripts/ph_speckit.py refresh-navigation --repo <项目> --expected-sha <已审阅宪法的SHA256>
python3 <ph-init>/scripts/ph_speckit.py refresh-navigation --repo <项目> --expected-sha <已审阅宪法的SHA256> --apply
python3 <ph-init>/scripts/ph_speckit.py verify-content --repo <项目>
```

刷新前逐段检查旧宪法导航中的人工说明，将有效内容承接至对应规则或保留文字中；命令仅替换导航条目，保留其余文字，来源哈希变化则停止。

低层安装 check 不等于内容验收。升级 verify/finalize 必须通过内容检查；失败保留现场与报告，补齐后重试，不写完成版本。初始化分别报告骨架检查、内容验收及命令执行状态，不把新项目的计划约定说成已运行验证。

## 原件保全与活动内容承接

需要覆盖或拆分存量内容时，先在仓外计划 JSON 中列 `roots`（仓内相对路径到归属理由的映射），执行 `ph_layout.py preserve --repo <项目> --batch <批次> --plan <计划>`。已有批次不可重新定义；续做读取原 inventory，不能用迁移后的目录重新冒充原件。

合并后在计划中逐文件列 `decisions`：`source`、`kind`、`evidence`，活动处置还须 `destinations`（各目标 `path` 与实际 `sha256`），仅历史保留须写 `reason`。执行 `ph_layout.py verify-transplants --repo <项目> --batch <批次> --plan <计划>`。将同一 `batch` 与 `decisions` 作为内容报告的 `migration` 对象登记，`verify-content` 会复核它们。全部旧原件都有明确处置且有效内容有活动落点后才能完成，不得用 archive 路径当活动落点。

## 语义复核

逐篇确认：规则与项目需求相符；命令来源唯一且真实；不适用有依据；旧定制有活动落点；旧发布运维规则未因基础树不预置而丢弃；测试门禁未因实现失败被降低；新增专题和记录目录在宪法中可达。脚本通过不能替代这些判断。
