# Spec Kit 随包适配版维护

用户安装和升级仅从 PH 发行包读取技能及运行依赖，不访问官方 Spec Kit，也不运行 pip 或官方生成器。官方来源固定在 speckit.json；assets/speckit-bundle.json 区分导入原件哈希与实际分发哈希。实际正文只有 assets/scaffold 中的一套。

## 按需引入官方更新

1. 在新的仓外隔离目录中获取明确的官方 tag，核对 commit，保留许可证。不得用 main 或缓存名称推定来源。
2. 使用该版本官方生成器生成产物，分别比较旧上游、新上游与当前 PH 适配正文。需要旧原件时按记录的固定来源重新获取，不从适配正文反向猜原文。
3. 主代理审阅并合并技能和运行依赖，保留 PH 名称、布局、点名调用边界及项目测试规范联动。不直接覆盖本仓或业务项目。
4. 新增运行资产同步受管清单和安装排除规则；清理机器路径、生成环境和不支持的工作流引擎文件。来源记录保留真实值，不将修改后正文称为官方原文。
5. 更新随包文件哈希、来源信息和 PH 迁移材料；执行发行检查、完整回归和历史升级矩阵。技能与模板改变时同步测试 seed 契约。

## 验收联动

测试门槛只在项目测试规范中维护。技能正文负责按阶段读取和落实；测试命令引用各端自测规范，启动引用构建规范。tasks 不以用户额外要求测试为前提；implement 记录当前功能 verification.md。analyze 保持只读，converge 只追加任务，checklist 的通过仅代表需求质量检查。

静态契约测试不能证明代理真正执行了测试。评估至少覆盖后端项目、前后端项目、缺少测试、新旧失败区分及证据过期；无法完成代理行为评估时必须单独声明未验证，不得用脚本全绿替代。
