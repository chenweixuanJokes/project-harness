# 接入规范

Last verified: <填写：YYYY-MM-DD>

使用时机：PH 首次安装、存量项目用旧内容接入（adopt）、升级合并或旧目录归并时读本文；安装完成后的逐条目文档补全见 [补全规范](补全规范.md)。

> 本文是 PH 接入会话的执行契约：只读取证、dry-run 整合、仓外合并候选与安装。它约束怎么盘点、怎么取证、怎么装进来；不替代各域正文，也不授权部署、通知、造记忆或造意图。
>
> `ph-init check` 只证明适配层与目录骨架可用。**check 通过不等于接入完成，更不等于补全完成。**

## 1. 目的与边界

接入目标：

- 新项目直接安装骨架：占位符留给补全会话按证据填写，不在安装时预填。
- 存量项目**用旧内容接入**：已有正文优先登记引用（结果记 `复用`），不复制第二套，不重写已有证据的正确内容；代码与文档从缺时按 [补全规范](补全规范.md) 的条目落点矩阵逐项反推补齐。
- 不为脑图或清单上的每个叶子预建空文档；同类约定写入已有专文，有独立维护者与足够事实时再拆单一主题专文（文首写「使用时机：」），宪法导航由 PH init / 升级刷新。

明确不做：

- 不在接入中改写发行技能或自动执行需求开发。自研开发流程的需求、设计、任务、验收与归档由各自点名技能承接；接入不自动调用它们。普通项目资料检查与纠正按文档治理规范处理。记忆操作由三个记忆技能承接（`ph-memory-ask` / `ph-memory-learning` / `ph-memory-archive`，查询按回忆意图触发，其余仅明确点名触发），接入和需求归档都不自动触发记忆写入。
- 不因接入自动新建意图、访谈纪要或记忆条目。
- 不从坏代码、过期 Wiki、未核实博客或模型推断倒推强制规则；建议不得自动升级为规范。
- 不先安装模板再盖旧正文：存量内容一律经仓外合并候选（见第 5 节）接入。
- 不覆盖项目已有定制。冲突或范围扩展时停止受影响项，保留已核验成果。
- 不实际上线、不发送通知、不上传本仓库代码 / 内网材料 / 秘密到公网。

版本与合并升级由发行源维护，不在本仓库业务文档里改 PH 版本号。

### 1.1 存量内容与旧目录

- **保留内容，不保留旧目录结构。** PH 活动内容统一落在 `project-harness/`（约束进 `constraints/`、资料进 `documents/`、规格进 `specs/`）；`docs/` 属于项目业务文档，PH 不占用。接入前的 `docs/specs/`、`docs/domains/`、`docs/plans/`、旧版 `docs/约束规范/`、`docs/项目Wiki/`、`docs/意图/` 及其它旧目录、顶层正文必须按内容归并到新落点，不留旧目录、空壳或软链作为第二套入口。
- 先建立逐文件的**旧路径 → 新落点**映射：规则归 `constraints/`，领域 / 架构 / 操作说明归 `documents/`，已有需求与计划按真实内容转为 `specs/` 下的规格或对应事实 / 规范页。附件与辅助脚本随所属正文迁移，不因整理而执行。README 若含独有规则，先提取进正文，再整理索引，不能当普通索引丢弃。
- 同主题内容合并为一个正文：保留旧文的有效细节与历史记录，将已核验的新摘要整合进去，去掉重复内容；不是把两个版本全文拼在一起。PH 摘要与深链指向归并后的正文，旧规范的效力不因移动而消失。
- 旧意图目录的存量内容按迁移契约转入规格：有效需求保留原题、来源、标识与日期，验收结论与用户原话随规格承接；缺失字段如实标未知，不推定评审、批准或测试通过。源状态与代码矛盾则记录双方证据，不以代码猜历史审批。调试实录不冒充访谈，不造纪要；过程原话按记忆流程 capture。
- 迁移由会话在**本轮授权**范围内执行；内核不自动搬移或删除。写前保存哈希、映射，并把将被覆盖、归并或移走的原文原样写入 `project-harness/archive/legacy-backup/<YYYY-MM-DD>-pre-init/`（约定见 `project-harness/archive/legacy-backup/` 目录 README）；核对新正文完整、附件一致、活动引用与各级索引修复后，再把活树里的旧文件移出。仓内这份快照就是可恢复原件，不再要求仓外原文备份。adopt 的 plan JSON 仍在目标仓外生成。不先挪走 canonical 或冲突文件骗过安装预检。
- 活动引用必须改到新落点，包括文档、canonical 与已授权范围内的其它入口；历史引用原话可保留为代码字面并在报告登记映射，不把失效链接继续当导航。涉及业务代码的引用超出授权时登记缺口，不擅自改代码。
- 未获迁移授权、存在内容冲突或中断时，报告受影响项为**未完成**，保留现场与续做说明，不把旧目录长期并存算作初始化完成。旧正文与当前代码 / 锁文件 / CI 矛盾按 [文档治理规范](../assets/scaffold/.agents/project-harness/constraints/harness规范/文档治理规范.md) 第 4 节的生效状态定性；规范冲突记 `冲突` 待用户裁决，不悄悄废止规则。

## 2. 只读盘点

先读，不改：

| 类别 | 看什么 | 用来决定 |
| --- | --- | --- |
| 约束与入口 | [AGENTS.md](../assets/scaffold/.agents/AGENTS.md)、`constraints/` 各专文（前后端 / 工程 / 测试 / harness） | 已有强制门禁与定制，保留不覆盖 |
| 旧文档目录 | `docs/` 下非 PH 命名目录（如 `specs/`、`domains/`、`plans/`）及其正文效力 | 哪些旧内容可 `复用`、哪些与实态冲突 |
| 代码与模块 | 应用入口、包结构、路由 / API、测试目录 | 有无前端 / 后端、真实边界 |
| 依赖锁 | lock / 清单 / 镜像列表，如 `package-lock.json`、`pnpm-lock.yaml`、`yarn.lock`、`go.sum`、`Cargo.lock`、`poetry.lock`、`composer.lock`、Gradle / Maven lock | 实际在用的语言、框架、中间件 |
| CI 与脚本 | `.github/workflows/`、其它 CI、`Makefile`、`package.json` scripts、构建脚本 | 构建、测试、发布入口 |
| 现有文档 | `docs/` 三域、Wiki 五字段、意图目录是否已有正文 | 哪些是定制、哪些仍是模板 |

盘点按七类证据汇总：**模块、代码、配置、真实依赖（锁文件）、测试、CI、旧约束**。每条证据记具体位置（路径、命令、清单条目、行号），能被他人复核。已有正文优先引用登记，不复制第二套。

在隔离副本上核验时，同时记录复制范围与排除项。`git ls-files` 不包含被忽略的锁文件或 `.java-version` 等必要构建输入；副本缺失不代表原项目不存在。先定向核对原路径与 `.gitignore`，在授权范围内审计并补入非凭据输入，保留哈希和来源；不能为补齐输入复制私有环境文件、依赖缓存或共享 Git 元数据。版本选择器与 lock 只证明声明或锁定值，不证明本轮运行过对应环境。

盘点结论先按 [文档治理规范](../assets/scaffold/.agents/project-harness/constraints/harness规范/文档治理规范.md) 第 4 节的生效状态四类定性。规范不能从“代码现在就这样写”推导出来；代码只能提供事实候选。纯代码仓库没有任何文档时同样逐项反推：七类证据仍是事实候选，无既有来源的规范条目保持 PH 通用门禁或标 `待核实`，不造规则。

## 3. 按实际栈查公网官方资料

只查**本仓库锁文件或清单里真实出现**的组件。不预填邻项目的 Kong / Eureka / Apollo / 某前端框架。

每条记录必须能复核：

| 字段 | 要求 |
| --- | --- |
| 组件 | 仓库内名称与锁文件版本 |
| 官方标题 | 页面标题原文 |
| URL | 公网官方或标准文档地址 |
| 版本 | 页面声明的文档 / 产品版本 |
| 访问日期 | 当地日历 `YYYY-MM-DD` |
| 采用理由 | 为何写入本仓库文档（例如锁文件已钉住该主版本） |
| 状态 | `已采用` / `待采纳建议` / `待核实` |

禁止：把业务代码、内网地址、令牌、完整连接串贴到搜索或第三方服务。网络失败或资料对不上锁文件时，条目标 `待核实`，写明缺口，不假装已核验。

公开方法论文档可参考，但有边界：

- [Diátaxis compass](https://diataxis.fr/compass/)：帮助区分教程 / 操作 / 解释 / 参考，**不**把 `docs/` 改成这四类目录。
- [arc42 Architecture Decisions](https://docs.arc42.org/section-9/)：决策要写背景与后果，落点仍是复制 [架构决策/_模板.md](../assets/scaffold/.agents/project-harness/constraints/架构决策/_模板.md) 新建 `NNNN-短标题.md`。
- [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)：安全控制清单的参考，**不**自动选定 ASVS 等级。
- [Software Engineering at Google, ch.11 Testing](https://abseil.io/resources/swe-book/html/ch11.html)：测试分层思路，**不**自动套用 Google 的覆盖率或测试数量阈值。

目标栈的官方版本与 API 以本次联网结果为准，不把上述四篇的目录或阈值抄进强制门禁。

## 4. dry-run 与四类整合

用同一发行根跑 `init` dry-run。内核输出的 `plan` / `skip` / `conflict` / `block` 是**待整合材料，不是施工单**。

会话把 dry-run 输出与盘点结论整合后交用户审阅，至少分四类列出：

- **直接落地**：目标缺失、无冲突，可按脚手架或整合后的候选写入。
- **复用引用**：已有正文可用，登记引用与索引，不重写。
- **冲突待裁决**：旧正文之间、旧正文与代码 / 模板矛盾，写双方证据，交用户决定。
- **不适用与保留**：无该端 / 组件、明确保留的定制与历史证据；旧目录结构不属于最终保留范围。

此时不写盘，也不在项目内生成任何候选文件。四类标题和内核字段留给报告与代理笔记。对用户说明和提问遵守 [对用户提问](../assets/scaffold/.agents/project-harness/constraints/harness规范/对用户提问规范.md) 的“通过正确通道实际提问”与“把问题写成可回答的决定”：先说还没改文件，再问这次先处理哪些；冲突单项只问“文档该怎么写”，不要把报告字段或脚本名念给用户。

## 5. 仓外合并候选与安装

用户明确同意本轮写入范围后（对用户问“现在可以按这个范围写入吗”，不要问内部命令名）：

1. 会话在**目标仓外**（临时目录）生成合并候选 plan JSON，并用同一发行根执行：

```text
python3 <release-root>/scripts/ph_init.py init --adopt-plan <plan.json> [--apply] [--mode auto|portable|symlink]
```

2. plan JSON 契约（字段实现以脚本 `--help` 为准）：

```json
{
  "version": 1,
  "repo": "<目标仓绝对路径>",
  "release_version": "<发行包版本>",
  "sources": {
    ".agents/AGENTS.md": "<正文 SHA256，缺失为 null>",
    "AGENTS.md": "<正文 SHA256，缺失为 null>",
    "CLAUDE.md": "<正文 SHA256，缺失为 null>"
  },
  "files": {
    ".agents/AGENTS.md": "<候选 UTF-8 正文>"
  }
}
```

   - `sources` 是合并基准快照：必含 `.agents/AGENTS.md`、`AGENTS.md`、`CLAUDE.md` 三个入口，以及 `files` 的全部目标路径；文件缺失写 `null`，不省略键。
   - `files` 只允许 canonical `.agents/AGENTS.md`（必需）、`docs/**` 与 `project-harness/{constraints,documents}/**`；候选由已有正文与脚手架整合，已有正文优先原样保留或引用登记。
   - plan 文件在仓外，不进项目、不改发行树、不写秘密 / 令牌 / 完整连接串。
   - 仅当目标尚无 `.agents/ph.json` 时可用 `--adopt-plan`。已装且版本旧于发行根：由 **init 会话**按发行根 merge-update 步骤做完（inspect → 语义合并 → verify → finalize），不重跑 `init --apply`，不要求用户另开技能。
3. 脚本先核对 `sources` 哈希与目标实态一致才落盘，防错仓、错时点与中途变更；哈希一致**不证明候选内容正确**，语义正确由会话 Agent 负责，细节校验主 Agent 可自查。
4. 先 dry-run 再 `--apply`；安装成功立即用**已装内核**跑 `check`。计划外的文件、部署、推送、发通知、建意图 / 记忆，必须再授权。

## 6. 接入禁令

- 不先安装模板再盖旧正文；存量内容未经仓外合并候选不得覆盖。
- 不为补齐盘点输入复制私有环境文件、依赖缓存或共享 Git 元数据；秘密不进 plan JSON、报告与会话记录。
- 不把失效链接继续当导航；引用改到新落点属于迁移授权范围，超出部分登记缺口。
- 超出本次用户授权范围或与原有定制冲突时，停止受影响项并报告；不为接入顺手改业务代码、部署或创建过程记录。
