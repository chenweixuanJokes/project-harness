# PH 自研 SDD 维护

PH 的需求开发技能、模板与运行时由同一发行版成套提供，不再固定或更新上游 Spec Kit 作为执行依赖。旧标签、迁移说明和需求记录里的上游信息是历史证据，不因重构抹除。

## 技能与语言

开发套件为 ph-require、ph-clarify、ph-design、ph-design-review、ph-tasks、ph-verify-plan、ph-small-change、ph-implement、ph-verify、ph-archive。英文 SKILL.md 是执行源，SKILL.zh.md 是逐阶段对应的中文说明，不注册为另一个技能。修改时同时检查英中职责、产物、授权和失败处理是否一致；结构检查不能代替语义校对。

共同边界位于 ph-require/references/process.md。主技能保留本阶段必要步骤，专项规则按需读取。不能因抽取共同规则让单个阶段失去必要前置、写入范围或完成标准。项目产物使用用户语言；机器元数据、稳定编号与路径保持协议约定。

## 运行时分工

- scripts/ph_governance.py：发行与安装侧宪法物化、约束导航和内容证据检查。
- assets/scaffold/.agents/scripts/ph_sdd.py：项目功能目录、旧产物接续、阶段状态、漂移检查、归档快照。
- assets/scaffold/.agents/scripts/ph_worktree.py：独立隔离工作区登记、交付、冲突与恢复。
- assets/scaffold/.agents/scripts/ph_human.py：伴读映射、来源哈希与受保护发布。

脚本检查机械一致性，不证明需求正确、用户已同意或测试真实执行。不得把手工输入 passed 看成独立运行引擎。证据由真实操作产生，语义由执行者和审阅者核实。

## 兼容与升级

新产物通过功能元数据定位，旧 spec.md/plan.md 可用 adopt 映射接续，保留原编号和字节，不从旧勾选推定当前通过。技能集合以 release.json 为唯一源。

修改技能或运行时属于发行有效内容，必须有新版本、迁移说明、索引和 Changelog。旧技能退役覆盖 canonical 与声明适配入口，先证明归属并保全；用户定制须有有效内容落点或真实历史处置理由。同名新技能不能绕过这项要求。

## 测试与行为评估

运行发行检查、完整 unittest、全历史升级矩阵与隔离本地 E2E。至少覆盖：

- 完整需求先审查再任务、先验收准备再实现。
- 小改动只准备、不实施，发现风险升级而不降低门禁。
- 自检失败回填任务、不直接修代码、不把用户当测试人员。
- 未回答保持等待；修复后受影响证据重验。
- 归档沉淀文档与已验证冒烟用例，不自动合并或退出工作区。
- 多工作区独立实现、共享资源冲突、串行合入及集成复验。
- 历史定制与产物保留、旧入口过渡、失败可恢复、重复操作幂等。

技能评估必须检查实际产物与执行行为，不仅检查正文是否出现关键词。隔离模拟事件不冒充真实用户批准或公网发行验证；未运行项目如实报告。
