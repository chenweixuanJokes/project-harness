# 1.1.11 → 1.1.12

## why

1.1.11 及更早的《对用户提问》按场景罗列固定问句模板，并用编号章节（第 2 节接入检查升级、第 3 节意图等）被其他文档引用。实际执行暴露出三类缺口：不该问却反复问（把能查清的事实推给用户确认）、有结构化问答工具却用正文文字代替实际调用、把“已提交问题 / 已收到回答 / 已取得授权”混为一谈（用提交状态或推荐项推定授权）。固定句库也随措辞调整反复失效，引用按章节号锚定后无法安全重排。改为按执行契约组织并去掉编号章节，让引用按语义落点。

## from

PH 1.1.11：`docs/约束规范/工程规范/对用户提问.md` 分为编号五节（1 口径；2 接入、检查、升级；3 意图；4 并行工作区；5 记忆），以各场景白话问句模板为主体。`docs/约束规范/工程规范/` 的意图与访谈、初始化与文档补全、Git与并行开发、工程规范 README 索引行，`.agents/memory/README.md`、`.agents/AGENTS.md`，以及 `ph-intent-new` / `ph-intent-impl` / `ph-intent-drop` / `ph-memory-capture` / `ph-memory-ask` / `ph-worktree-exit` / `ph-merge-update` 各 Skill 以“第 N 节”或固定句子引用该文。已授权创建隔离工作区不再重复确认、来源取主工作区当前分支等 1.1.9–1.1.11 行为边界已在旧文中以例句存在。

## to

PH 1.1.12：该文重写为执行契约，按“何时需要用户决定、通过正确通道实际提问、把问题写成可回答的决定、根据真实回答推进、纠正失误与恢复中断、边界示例、完成检查”组织，不再有编号章节。要点：

- 能查清的事实先查不问，授权内的普通选择自主处理，只有关键决定或必要授权确有缺口才问；已回答的同一问题不重复问，已授权的同一操作不追加执行确认。
- 当前宿主有能合理表达当前问题的结构化问答工具时必须实际调用；正文列选项、预告“我会问”或承诺“下次用工具”不能代替调用；调用失败、提交成功、收到回答是不同结果，只有实际回答才可作为决定依据。
- 降级为可见文字提问必须有实际原因：确实没有问答工具、技术故障经合理检查仍无法恢复，或工具格式无法合理表达开放问题（如实说明格式限制后用文字提出开放问题）。不能仅凭“error”状态判定故障：按具体原因区分权限拒绝、用户取消或跳过与无法确认原因的无有效回答，三者都保留未决，不换通道重复施压，不解释成同意。
- 正式计划审批走宿主专用审批通道；没有专用审批能力时只按宿主明确允许的替代流程办理，否则说明阻断并停止依赖审批的操作。密码等秘密只走安全采集流程或目标服务登录。
- 一个好问题写清已经知道什么、请用户决定什么、选择影响什么；开放问题不编造选项；重大后果（如删除已有数据）写明且不因决定兼容自动授权执行。
- 已提交问题、收到回答、取得操作授权是三个不同状态，不用推荐项、预选值、沉默或代理推断补齐；被指出没有用工具且决定仍未解决时，修正问法并实际重新提交，不以修改规范代替本次提问。

引用该文的规范、记忆 README、canonical AGENTS 与各 Skill 门禁句改为不锚定章节号的语义引用（如指向“把问题写成可回答的决定”）。
