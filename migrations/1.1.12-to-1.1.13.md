# 1.1.12 → 1.1.13

## why

1.1.12 及更早的 Skill 触发口径混杂：记忆与意图等技能写着“只要用户说…——即使没点名本技能——都必须使用”，实际执行中出现两类问题——用户只是在讨论、描述或上下文里提到某技能时被自动调用，造成越权或打断；技能之间还会自动串联（如进入 worktree 的流程直接推导出调用退出技能、录入意图后自动进入实施），把上游一次调用当成下游的授权。同时，意图实现完成的验收没有专属入口：`ph-intent-impl` 启动推进常被误读为“实现完成”，缺少把真实实现逐点交给用户确认的机制。本版统一改为显式调用门禁，并新增实现后用户验收技能。

## from

PH 1.1.12：十二个技能缺一（无实现后用户验收入口）。触发口径按各 Skill 各自描述：`ph-memory-capture` / `ph-memory-archive` / `ph-memory-ask` 写明“只要用户说…——即使没点名——都必须使用”；`ph-worktree-enter` 正文第 5 步“完成时调用 `ph-worktree-exit`”；`ph-intent-new` 写“启动推进属于 `ph-intent-impl`”；`ph-intent-impl` 写“才按要求处理分支或调用 `ph-worktree-enter`”。规则索引 `.agents/AGENTS.md` 技能表十一行、无调用门禁段；`docs/约束规范/工程规范/意图与访谈.md` 职责表三行意图技能；`docs/意图/_模板.md` 计划交接节与 `Git与并行开发.md` 进出流程句按旧口径引用技能。各 Skill evals 部分样例以普通描述为正例。

## to

PH 1.1.13：十二个必需 Skill（新增 `ph-intent-verify`）。两条口径：

- **显式调用门禁**（迁移项 `explicit-invocation-rules`）：十一个既有 Skill（根 `ph-init` 与 scaffold 十个）的 `description` 与正文统一为——仅当用户当轮明确点名该技能（如「用 ph-memory-capture 记住…」）并要求使用时才调用；普通描述（如“记住 X”“同步文档”“初始化 PH”“开个 worktree”）、上下文提及或讨论技能名称都不触发。技能之间不自动串联：进入 worktree 后的交付由用户点名 `ph-worktree-exit`；录入、启动推进、验收、废弃互不推导调用；门禁只管入口，已显式启动的同一流程内，用户回答提问或说“继续”仍按原流程接收反馈与恢复，不要求每轮重复点名，也不触发其他技能；`ph-intent-verify` 与 `ph-docs-sync` 在彼此的“不用”清单中互指边界。唯一保留的内部步骤：用户点名 `ph-init` 并请求升级已装项目时，该会话读发行根 `ph-merge-update` 作为该次升级的步骤与参考文档执行。`.agents/AGENTS.md` 技能表上方新增门禁段，`意图与访谈.md` 职责表补门禁句，`docs/意图/_模板.md` 计划交接节、`Git与并行开发.md` 进出流程句、`初始化与文档补全.md` 固定 Skill 句同步；各 Skill evals 补触发正反例（点名即触发、仅描述或讨论名称不触发）。
- **新增验收技能**（迁移项 `intent-verify-skill`）：安装 `ph-intent-verify`（SKILL.md 与 evals）到 `.agents/skills/ph-intent-verify/`，`.agents/AGENTS.md` 技能表与 `意图与访谈.md` 职责表登记第十二行。该技能对唯一意图做产品经理式逐步用户验收：定位意图、验收标准与真实实现；复用已有环境，只按项目说明准备本地服务，不擅自重启 / 安装 / 改配置；按宿主工具能力给用户可见入口，区分隔离浏览器与用户可见页面，可访问的地址不等于已打开，有打开能力且在授权范围内就实际打开要验收的功能、不只给链接，宣称“已打开”必须有实际打开成功的证据；一轮一个验收点（验证什么 / 在哪操作 / 输入什么 / 预期结果），有问答工具就实际调用等用户反馈，确实无工具或开放问题无法用工具表达时按《对用户提问》以文字等效提交，取消、沉默、跳过与代理自测都不通过；失败记录可复现证据，不自动修代码、不调用其他技能；记录写入该意图现有「记录」节（日期、环境、逐项反馈、证据、结论），不新增状态、目录或纪要 purpose；整体状态只有通过 / 不通过 / 阻断 / 未验收，整体结论由逐项状态汇总而成，全部点真实确认才整体通过。

## preserve

## conflict

项目已有同名自定义 `.agents/skills/ph-intent-verify/`（形态规整时由 `inspect` 列入冲突清单，异常形态先被结构校验拒绝，均 fail-closed）或项目规则明确禁止新增 ph-* Skill 时，`intent-verify-skill` 项 `blocked`，保留原件请用户决定，不得覆盖。项目显式规则与显式调用门禁相反（如项目要求按普通描述自动触发某 Skill、或强制技能间自动串联）时，`explicit-invocation-rules` 项 `blocked`，交用户裁决；不推进版本。两项 blocked 都不阻止其余迁移项完成，但 verify 需全部项完成才能 finalize。覆盖 / 写入不绕过本 Skill 既有写入确认与文件安全检查（软链、非普通文件照常拒绝）。
