# 1.2.1 → 1.2.2

## why

每次升级都要先 `ph_release.py prepare` 取新发行根，但用户级引导入口 `~/.agents/skills/ph-init` 不会随之更新：它会停留在最初安装时的版本，触发描述与执行指引逐渐过期，只能靠手工整树替换。本批把入口刷新并入升级流程顺带完成，并提供受脚本保护的安全语义（不新建、不降级、可恢复）。

规格流程的机器产物（spec / plan / tasks / verification 等）对不熟悉流程的同事可读性差，评审与验收往往需要人先读懂再核对。本批同时为十个规格技能附带生成人读伴读：机器产物每次产出后，同功能目录多一份快照式解释文档，由共享脚本保证映射、来源哈希与受管写入安全，不改变机器产物的权威地位，也不放开技能自动串联。

规格流程按技能分段点名执行，每段跑完会话上下文已经很长，而「下一步该跑哪个技能」依赖流程门禁知识，需要用户自行回忆。本批同时为十个规格技能补一段固定收尾文案：完成报告与 extension hook 处理结束后原样输出「下一步建议执行」，先建议压缩会话，再按场景列出后续可点名执行的技能；只建议，不自动调用，不改变点名调用门禁。

## from

1.2.1 的七个 PH 技能、十个随包规格技能与 `project-harness/` 终态布局。更早版本按完整迁移链升级，不跳过历史迁移项。

## to

### `user-entry-refresh`

`scripts/ph_release.py` 新增 `user-entry` 子命令，只能从准备好的发行根运行（以根内 `.ph-source.json` 回执为凭，开发树与项目内执行直接报错）。它把 `<home>/.agents/skills/ph-init` 整树刷新为该发行根：

- 入口不存在、是软链接或非普通目录、版本无法判定（`.ph-source.json` 与 `release.json` 都读不出合法 semver）时不改动，返回 `action: skip` 与原因；不新建入口。
- 入口版本不旧于本包时跳过，绝不降级。
- 刷新前先把旧树整体移入 `<home>/trash` 备份；拷贝失败自动还原备份，不留下半份入口。来源回执随树写入，新入口可追溯 tag/commit。

根 `SKILL.md` 工作流第 1 步要求：prepare 成功后执行一次 `user-entry`，跳过即报告原因，不重试、不当失败。

### `human-readable-companion`

新增第八个必需 Skill `ph-human`（点名触发，负责盘点与按需刷新伴读、维护共享写作规范）与共享脚本 `.agents/scripts/ph_human.py`（仅做机械部分：文件映射、来源/正文哈希、受管写入保护、陈旧检测与安全发布；不生成文字）。十个规格技能正文各附加一段「附带人读版」指引：

- **映射**：功能目录根部的 `spec/plan/research/data-model/quickstart/tasks/verification.md` → 同目录 `<名字>-human.md`；`checklists/<名>.md` → 根部 `checklists-<名>-human.md`；`contracts/<名>.md` → 根部 `contracts-<名>-human.md`；`constitution.md` → 旁边 `constitution-human.md`。伴读一律在功能目录根部，不进入 `checklists/`、`contracts/`。
- **快照型**：ph-analyze 保持严格只读，唯一写入例外是把本次真实报告发布为 `analysis-human.md`；ph-taskstoissues 仅把本次已授权真实创建的 Issue 结果发布为 `issues-human.md`，发布伴读不产生额外外部副作用。
- **语义**：伴读是快照解释，不是权威规则或验收源；正文开头写来源与日期，保留编号、风险、未知项与实际状态；机器元数据（来源路径、来源 sha256、类型、产出技能、时间、正文哈希）由脚本写在文末。
- **安全**：缺源不编产物；`-human.md` 永不作为机器源（无递归）；嵌套产物扁平化同名、软链/硬链/越界路径一律阻断；伴读已存在时，无有效页脚或正文哈希与记录不符（用户改动）不得覆盖；写入原子替换。
- **自动边界**：十技能只自动刷新本次产物；其余陈旧伴读用 `status` 提示，不擅自代刷；伴读失败单独报告，不撤销主流程、不宣称全部完成；不调用 ph-human、不自动串联任何技能。
- 写作规范唯一来源：`ph-human/references/human-writing.md`，十技能直接读文件。

### `speckit-next-step-hints`

十个规格技能 `SKILL.md` 末尾新增「PH 下一步建议（固定输出）」收尾节：完成报告与 extension hook 处理结束后、结束本次回复前，原样输出固定文案——「下一步建议执行:」第一条固定为压缩会话（`/compact`），随后按场景列出后续可点名执行的技能（如 `ph-specify` 指向 `ph-clarify` / `ph-plan`，`ph-tasks` 指向 `ph-analyze` / `ph-implement` / `ph-taskstoissues`，`ph-converge` 在 converged 时说明进入评审 / 开 PR，`ph-taskstoissues` 是流程终点）。文案只建议不调用；衔接关系与现有门禁一致（implement / converge / taskstoissues 仍要求 tasks.md 存在，converge 仍要求先跑过 implement），不新增验收入口。

- `assets/speckit-bundle.json` 的 `files` 基准同步为十个 `SKILL.md` 的新哈希，安装与升级仍先校验清单再写入。

## affected

- 项目内自包含 `ph-init` 载荷按既有受管文件合并规则更新（根 `SKILL.md`、`scripts/ph_release.py`、迁移材料、scaffold 清单版本号），保留项目定制。
- 用户级入口刷新属于本机动作，不写目标项目任何内容；`user-entry` 只在会话显式执行时运行。
- `human-readable-companion` 需要在项目内落地的发行内容：
  1. 从发行根 scaffold 安装新技能目录 `.agents/skills/ph-human/`（SKILL.md、references/human-writing.md、evals）。
  2. 从发行根 scaffold 安装共享脚本 `.agents/scripts/ph_human.py`；`ph_init.py check` 会校验其在位。
  3. 从发行根运行 `python3 <发行根>/scripts/ph_speckit.py install --apply --repo <项目>`：十个技能 SKILL.md 更新为带人读版指引的新字节（逐文件内容基准匹配才覆盖，用户改过则冲突阻断），并重记录 `.agents/ph.json` 的 speckit 基准。
  4. `.agents/ph.json` 的 `skills.required_names` 增补 `ph-human`（由 verify/finalize 的候选重建写入），`template_version` 仍在 finalize 通过后才推进为 1.2.2。
- `speckit-next-step-hints` 需要在项目内落地：与上一项同一次 `python3 <发行根>/scripts/ph_speckit.py install --apply --repo <项目>` 完成，十个技能 SKILL.md 更新为带固定收尾节的新字节（逐文件内容基准匹配才覆盖，用户改过则冲突阻断），并重记录 speckit 基准。
- 无业务文档迁移：人读伴读只在规格技能实际产出机器产物时生成，升级本身不为已有产物补写伴读（用户需要时点名 ph-human 刷新）。

## preserve

保留所有业务文档、约束终态、宪法、specs、记忆、账本、历史索引与用户定制技能；已有功能目录里用户手写的任何文件都不因本项被改写。项目内已存在的 `.agents/skills/ph-human/` 同名目录（1.2.1 及以前没有发行过该名）视为项目内容：保持原位、阻断本项、请用户决定，绝不覆盖。伴读文件是受管产物，但用户改动过的伴读（正文哈希与页脚记录不符）同样不覆盖。已发布历史迁移文件不改写。

## conflict

同名 `ph-human` 技能目录冲突、`.agents/scripts/ph_human.py` 被用户内容占用、十技能文件与内容基准不符（用户改过）、伴读发布被用户改动阻断时，相关写入停止并逐项报告，不降级为静默跳过；`ph_speckit.py install` 的既有冲突语义（fail-closed、可重试）不变。用户级入口路径被软链接、硬链接或非目录占用时跳过并说明，不改动；版本无法判定时不猜测、不覆盖，交用户决定；`~/trash` 不可写或旧树无法移动时报错停止，不强制覆盖入口。

## verify

- 从准备好的发行根运行 `user-entry --help` 与实际执行可用；从开发树或无回执目录运行报错退出，不动入口。
- 旧入口（版本更旧）刷新后：入口内容与发行根一致、回执版本正确、旧树完整出现在 `~/trash`；重复执行返回 skip 不降级。
- 入口不存在或版本不可判定时返回 skip 且文件系统无变化。
- 升级既有项目：受管载荷与发行根逐字节一致、项目定制保留、finalize 写入 1.2.2；失败不推进版本。
- `human-readable-companion` 落地证据：`.agents/skills/ph-human/SKILL.md` 与发行根一致、`.agents/scripts/ph_human.py` 与发行根一致且 `python3 .agents/scripts/ph_human.py status --repo <项目> --all` 可运行（伴读尚未生成时报告 missing 属正常）；十技能 SKILL.md 与新基准一致；`ph_speckit.py verify` 通过；finalize 后已装内核 `check` 通过（required_names 含 ph-human）。
- `speckit-next-step-hints` 落地证据：升级后每个规格技能 SKILL.md 含「PH 下一步建议（固定输出）」节且位于文末，文案含「压缩会话（/compact）」与「按场景选择」，建议清单只出现 `ph-*` 名称；本仓 `tests/test_ph_speckit.py` 的收尾文案契约用例通过。
- 功能验证（安装后任一功能目录可用）：`publish` 发布的伴读文末含机器元数据且 `status` 报 fresh；改机器产物后 status 报 stale；手改伴读正文后 publish 被阻断；对 `-human.md` 作源、缺源、嵌套同名均报错不写入。
- 历史升级矩阵自动覆盖 1.2.1 起点，本项在矩阵中按技能/脚本安装、十技能更新与载荷刷新执行并留证。
