## 1. 统一门禁

| 层 | 目的 | 完成标准 |
| --- | --- | --- |
| 静态检查 | 合入主分支前执行项目已采用的 lint、格式及类型检查；命令见各端自测规范 | 已采用检查全部通过；没有工具时说明项目决定，不捏造通过记录 |
| 单元 | 锁模块行为 | 默认**全量**绿。定向跑单个测试只作开发内循环，不算完成 |
| 接口 | 锁 HTTP / RPC 契约（有后端且仓库声明时） | 用例与契约同步；改契约必须改用例 |
| 端到端 | 锁跨端或跨服务关键路径（仅仓库声明启用时） | 选定剧本全绿；未启用则本层不适用 |
| 冒烟 | 锁关键路径可走通 | 缺陷先用同一冒烟复现，修复后再用同一用例验证。断言失败即失败，不得跳过 |
| 回归 | 锁合入主分支 | 全量单元 + **全部**冒烟（及仓库声明的 e2e / 接口），一律全量、不分档。任一层失败阻塞 |

功能做完必须达到：受影响端的全量单元全绿 + 受影响冒烟通过。新接口 / 新页面 / 新可复用模块没有对应用例，视为开发未完成。

**重构是大改动**：跨文件重命名、签名调整、抽象提取、模块拆分、公共工具迁移、DSL 或数据结构变更，无论看起来多等价，合入共享基线前必须跑回归。

前端 / 后端规范只写各端命令、产物和特有时机，不复制本表。

## 2. 阻塞规则

- **新增用例默认阻塞**：新写的用例进入门禁层，不得写成「仅记录、从不阻塞」。
- **降级要说明**：把某个用例或层次移出门禁（跳过、隔离、改档）必须写明理由与恢复条件，登记在 [稳定性规范](./稳定性规范.md)。
- **不能可靠阻塞的用例不该存在**：一条用例若无法稳定地阻塞合入 / 发布，先修复它或移出门禁并登记，不留在门禁里反复假绿。

## 3. 影响范围分档（功能完成时的冒烟选择）

- 本节只用于「功能做完必须达到：受影响端的全量单元全绿 + 受影响冒烟通过」的冒烟选择；**回归不走分档**，一律全量单元 + 全部冒烟。
- **全局改动或大重构**：受影响冒烟即全部冒烟（及仓库声明的全部 e2e）。
- **其它改动**：只跑推断受影响的剧本，并把推断依据写进当前功能的 verification.md。拿不准按全局处理。

全局的例子：鉴权、HTTP 客户端、路由框架、设计令牌、依赖大版本、构建配置。

## 4. 回归执行细则

- **触发条件（任一命中必须跑回归）**：合入共享基线、合入主分支前、重构或全局改动、依赖大版本升级。不得以「行为未变」「改动很小」为由跳过。
- **回归定义**：该端全量单元 + 该端全部冒烟用例（及仓库声明的接口 / e2e）；前后端都存在时两端都要跑完。
- **组合顺序**：先全量单元，全绿后再跑全部冒烟；单元失败即终止，不继续后续层。
- **失败处理**：任一层失败即阻塞合入 / 发布。修复后从失败的那一层起重跑整个组合，不得只重跑失败的单条用例；重跑仍偶现失败，按 [稳定性规范](./稳定性规范.md) 的 flaky 流程处置，不当通过。
- **证据**：每层结果留报告路径或用例内证据记录（见 [用例规范](./用例规范.md) 第 6 节）；没有证据的组合门禁不算跑过。
- 按端执行细则：[前端回归测试规范](./前端测试规范/前端回归测试规范.md) 与 [后端回归测试规范](./后端测试规范/后端回归测试规范.md)。

## 5. 需求流程与执行证据

需求与验收目标写在 requirement.md（小改动为 change.md），方案写在 design.md；必要单元测试与能复现问题的 Bug 回归测试属于 tasks.md 的每个实现任务，ph-implement 执行任务时同步编写并运行，不拖到验证或归档，也不等待用户再次要求测试。测试命令以各端自测规范为准，启动方式以构建规范为准。

verify-plan.md 只规划智能体成果级自测（真实入口的主流程、集成、重要异常、权限与受影响回归）和用户成果验收指引，单测不在其中重复展开。用户按 acceptance.md 验收可用成果，不承担第二套技术补测；智能体自测通过后才请用户验收，不让用户检查本应由智能体完成的日志、SQL、状态码或异常路径。

ph-verify 只写验证记录与修复任务，不改应用代码：每个失败按发现与来源去重后追加或更新 tasks.md 修复任务，不重复登记。verification.md 记录实际命令或用例、代码及环境状态、结果和证据；无证据不勾通过。需求、设计、代码、依赖、配置或环境变化后重新判断既有证据有效性并重验受影响项，不把旧勾选或旧通过状态当作当前通过。

开发定向测试不能替代完成门禁；相同状态下有效的完整门禁证据可以复用，相关修改后重新验证。失败、未执行和有依据不适用分别记录；没有测试不等于不适用。静态审查、需求质量清单或任务打勾不能作为运行通过的证据。

本次问题在授权范围内修复并复验；无关既有失败如实记录，不擅自扩大修复范围，也不能宣布完整门禁通过。实现自测、成果级自测、合入前回归和已合入交付分开报告；用户成果验收仍须完成，且不替代门禁。测试要求不授予合并或外部操作权限。
