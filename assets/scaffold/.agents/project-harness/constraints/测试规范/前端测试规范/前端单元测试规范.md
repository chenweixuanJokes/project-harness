## 2. 硬性禁令

- 不断言实现细节：只断言可观察行为（渲染结果、事件后的状态与副作用），不断言内部状态、私有方法或第三方库的内部结构。
- 不为迁就当前实现改断言；契约或需求变化时先改用例预期，再改实现。
- 不捕获异常后吞掉、不把超时当成功。
- 单元层不发起真实网络与存储调用，跨边界依赖用替身（原则见 [用例规范](../用例规范.md) 第 3 节）。

## 4. 组件与 hook 测试要点

- 组件测覆盖：渲染输出、用户交互（点击 / 输入）、事件后的状态与回调；异步内容等稳定后再断言。
- hook / 组合函数测覆盖：初始值、状态迁移、清理副作用；不依赖组件宿主也能测的尽量直接测。
- 涉及路由、请求层、全局状态的组件，替身其边界依赖，不替身被测组件本身。
