## 1. 共用字段

每条用例（含前端组件/页面测、后端单元/接口、e2e、冒烟）至少能回答：

| 字段 | 要求 |
| --- | --- |
| 用例 ID | 稳定、仓库内唯一。已有编号则沿用，不在文档里另起一套 |
| 覆盖功能 | 指向 [功能地图](../../documents/功能地图.md) 的功能名或路由/接口 |
| 前置 | 账号、开关、服务是否已起、特性开关 |
| 测试数据 | 构造方式与隔离范围；不写真实密钥或生产数据 |
| 步骤 | 可重复的操作或调用 |
| 断言 | 可观察的期望；失败即失败 |
| 清理 | 数据、文件、会话如何收回；没有副作用写「无」 |
| 环境 | 本地 / CI / 需依赖的服务；指向 [开发指南](../../documents/开发指南.md) |
| 证据 | 报告路径、日志、截图或用例内记录位置 |

## 2. 结构与质量属性

- **结构（AAA）**：准备（Arrange）→ 执行（Act）→ 断言（Assert）三段式；一段做一件事，断言段不夹准备动作。
- **质量属性（AIR / FIRST 同义）**：可自动化、相互独立、可重复——同一条用例单独跑与全量跑结论一致；不可自动化的检查不算门禁用例。
- **命名**：描述行为与期望（如「搜索-未带令牌-返回 401」风格），不用无含义编号；仓库已有体系沿用。
- **TDD 不强制**：写测试的先后顺序是个人实践；强制的是交付物有对应用例且门禁通过。探索性 spike / 原型可豁免，但合入共享基线前必须有覆盖。

## 3. Mock 与可测试性

- **替身边界**：只替身跨边界依赖（网络调用、存储、外部服务、时间、随机、环境变量），不替身被测对象本身与其同模块的协作对象；替身清单写进用例「前置」，让读者知道测的是真实协作还是替身。
- **替身行为即约定**：stub 返回值与 spy 断言对应真实契约，不凭想象编造返回结构；契约变化时替身同步更新，不得为迁就当前实现改断言。
- **可测试性**：时间、随机、ID 生成等非确定性来源可注入；入口层保持薄，业务规则可脱离框架容器直接测试。可测试性缺陷按债务登记，不绕着写。
- **禁止**：写出离开替身就不成立的断言；捕获异常后吞掉；把替身行为当真实集成已验证——跨边界真实协作由接口 / 冒烟层覆盖。

## 4. 场景类型与覆盖维度

场景类型（适用才列）：正向、边界、失败 / 负向、权限（未登录、无角色、越权）。

边界与错误输入优先覆盖：边界值、正确值、按设计文档推导的关键分支、强制错误输入。不为不存在的场景补用例。

## 6. 证据与环境

- 冒烟 / e2e 执行后必须留下证据（报告目录、日志路径、或用例内「证据记录」）。没有证据的「我跑过了」不算通过。
- 测试所需进程由开发者按 [前端构建规范](../前端规范/构建规范.md) 或 [后端构建规范](../后端规范/构建规范.md) 自行启动；启动前按对应规范要求重建产物，避免 stale class / stale bundle。
- 静态读过命令不等于执行成功；`last_verified` 只在真正跑过或对照过脚本后才填。

## 7. 需求流程中的用例沉淀

- 真实测试代码（单元、接口）在实现任务内写入项目测试目录，不在 `constraints/` 登记源码；不把自动化测试编写拖到归档，也不由归档替代实现。
- 归档（ph-archive）时把已验证、可复用的冒烟场景登记或更新进前端 / 后端测试用例库（仍只收冒烟），按各自 `_模板.md` 一例一文件；沿用第 1 节共用字段：稳定用例 ID、覆盖来源（需求编号与功能 / 路由 / 接口）、剧本源码位置、前置、断言、清理与证据，已有编号沿用并去重。
- verify-plan 中拟用的命令只是执行建议：临时命令、个人绝对路径、临时端口与秘密不得固化为长期用例配置或长效命令。
- 失败或未执行的候选如实保留状态，不得出现在通过的沉淀报告；未执行、未验证的场景不宣称通过。
