# specs/

当前需求的活动工作目录。每个需求一个稳定子目录 `<编号-主题>/`：编号一经分配不变，目录不随状态或改名搬移，引用不断链。机械状态与指纹在目录内 `ph-feature.json`（经 `ph_sdd.py` 维护）；语义与验收以文档正文和证据为准，勾选只是进度，不是运行通过的证据。

- **完整流程**（full）：`requirement.md`（需求与用户成果验收目标）、`design.md`（方案）、`review.md`（设计审查）、`tasks.md`（任务，内含必要单测）、`verify-plan.md`（智能体成果级自测与用户成果验收指引）、`acceptance.md`（用户验收指引）、`verification.md`（实际执行证据）。
- **小改动**（small）：`change.md` 替代单独的需求与设计文档，任务、验证与授权语义与完整流程相同。
- 需求、验收、任务与发现使用稳定编号；修订保留原编号与已完成历史。
- 旧版 Spec Kit 规格（`spec.md` / `plan.md`）兼容读取：分别映射为需求与设计来源，原编号、问答、附件与证据保留；既有勾选不推定通过，按现行门禁实际核验后才可标通过。
- 需求阶段不再用旧版 `docs/意图/` 的状态目录表达状态；历史材料在 `../archive/`，仅供追溯，不当作待办或现行需求。归档后的只读快照与索引在 `../archive/features/`。
