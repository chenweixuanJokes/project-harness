# legacy-backup/

初始化或升级归并时，会被覆盖、合并或从活树移走的**原文快照**。它是仓内可恢复原件，不是规范、不是现行文档、也不是记忆。

不要和下面两处混用：

| 路径 | 用途 |
| --- | --- |
| 项目根 `archived/` | 业务下线模块归档，与 PH 无关 |
| `project-harness/archive/memory/` | 已合并的旧版记忆原件 |

## 何时建快照

空仓、没有会被覆盖或移走的原文时，只保留本 README，不造空快照。

存量项目在写入、归并或移出旧文件之前，先建一次带日期的目录：`project-harness/archive/legacy-backup/<YYYY-MM-DD>-pre-init/`。同日多次备份时在日期后加 `-2`、`-3`。快照里再放一份 README，写清备份了哪些路径、对应哪次 init / 升级、哈希或文件清单在哪。

目录内保持**接入前的相对路径**。例如会覆盖根入口时放 `AGENTS.md`；旧文档树按原相对路径存放，如旧 `docs/约束规范/` 的原文仍以 `docs/约束规范/` 开头。

## 规则

- 原样复制，不改写、不脱敏、不整理、不执行附件或脚本。
- 含群 key、令牌或其它秘密的原文跟着文件走；说明里只写「含敏感原文，禁止打印、上传、执行」，不复述内容。
- 本目录只读追溯，不进 README 索引体系，不当作现行文档或现行规则。
- 不进 `.gitignore`。需要恢复时从这里按旧路径取回。
- 内核 `ph-init` 与升级流程不自动写入本目录；由本轮授权的会话在改活树之前完成。
- 禁止 `rm`。不再需要某次快照时，按项目的文件移除规则移出仓库。
