# Project Harness 项目资料

本目录保存当前项目的 PH 规则、知识、规格和历史材料。所有路径以下列目录为准，不再从旧版目录读取活动内容。

| 位置 | 用途 |
| --- | --- |
| `constitution.md` | 工作前读取的项目宪法，逐文件列出约束与适用场景 |
| `constraints/` | 当前有效约束正文，可按主题建立子目录 |
| `documents/` | 当前项目事实、架构与领域资料；引用前对照代码确认有效性 |
| `memory/temporary/` | 尚未结构化的参考记忆 |
| `memory/structured/` | 已按主题整理的参考记忆 |
| `runtime/` | PH 自有流程模板与运行资料，不依赖上游生成器 |
| `specs/` | 当前需求的需求、设计、任务与验证等 SDD 产物及证据（`<编号-主题>/`） |
| `archive/` | 升级前 PH 全量原件、需求归档快照与后续历史资料，不作为活动规则或运行入口 |

## 维护约束

`constraints/` 中每个文件都必须在宪法中单独引用，并明确什么情况下需要使用。增加、移动或移除文件时同步宪法引用；不得用目录索引代替文件级引用。创作模板一般放在 `runtime/`；架构决策与两端冒烟案例的 `_模板.md` 保留在记录目录，不作为有效约束。

约束正文是规则的来源；宪法的导航说明用于确定何时打开正文，不复制整份规则。语义不明或相互冲突时先核实，不用“待确认”条目冒充升级完成。

## 规格与历史

新需求在 `specs/<编号-主题>/` 以稳定路径承接：完整流程沉淀 requirement、design、review、tasks、verify-plan、acceptance、verification；小改动用 `change.md` 替代需求与设计。旧 `spec.md` / `plan.md` 分别映射为需求与设计来源，原编号、问答与证据保留，既有勾选不当通过。迁移旧需求时保留有效需求、状态、验收条件和必要过程材料；仅把原件放入归档不算完成迁移。需求归档把只读快照与索引写入 `archive/features/`，并把已实现事实同步进 `documents/`。

归档中的旧技能、旧约束和旧脚本不得作为当前入口执行。需要追溯时按归档清单定位原路径与原件；恢复历史内容属于单独操作，不覆盖当前文件。

技能规范源在 `../skills/`，各技能的 description 声明用途与调用条件；本批新建和修订技能以英文 `SKILL.md` 为执行源，`SKILL.zh.md` 为中文对照，不注册第二个技能。安装清单在 `../ph.json`。个人记忆位于用户 HOME 的 `~/.agents/memory/`，本项目安装与升级不修改它。
