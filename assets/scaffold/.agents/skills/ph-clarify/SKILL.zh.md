# ph-clarify 中文对照

仅当用户明确点名 ph-clarify 并要求使用时执行；普通描述、名称提及和下一步建议不触发。明确启动后的继续不要求重复点名，不自动调用其他技能。

# 澄清需求

读取[开发共同约定](../ph-require/references/process.zh.md)，明确选择功能并完整阅读需求或映射的旧 spec；小改动读取 change.md。

## 执行步骤

1. 检查目标、角色、主成果、非目标、数据归属、权限、重要失败边界、兼容及验收可判断性，对照现有实现与项目规则。不为填满清单制造问题。
2. 将缺口分为可核实事实、用户决定、非阻塞细节。事实自行调查，除非改变用户约定，否则实现选择留到设计。
3. 使用宿主问答能力一次处理一个阻断决定，说明已发现歧义及后果，有合适选项时给出有依据的不同选择，保留真实回答。不询问是否执行项目既定强制测试。
4. 只更新受影响需求段落，追加问题、回答、日期与受影响编号的澄清记录。保留既有决定及仍有效原话，不暗中把新要求改成旧验收条件。
5. 重新检查答案是否造成整体矛盾。仍有阻断或用户无法回答时保持 blocked/draft 并说明原因；否则通过运行时记录 reviewed 和真实审查说明。它只表示需求清晰度，不表示实现或用户验收通过。
6. 需求变动前已有设计、任务或检查时，指出哪些下游产物需要复核，不自动重做其他阶段，也不把原审批当作当前有效。
7. 只刷新变更来源的伴读，汇总确认决定和未决项，就绪时建议 ph-design。

## 完成标准

重要未知已解决或明确阻断。需求审查不能把测试、实现、用户验收标为通过。不修改应用代码或无关文档。
