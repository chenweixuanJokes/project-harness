# ph-sure

对刚做完的一轮工作做收尾四问：改好了吗、测试了吗、合并了吗、还有无遗漏尾巴。本技能只核实事实、如实报告，不代替用户确认，也不替任何未授权动作放行。

## 调用门禁

- 仅当用户当轮明确点名本技能并要求使用时才执行。用户只描述需求（“收个尾”“看看还有没有尾巴”）、在上下文里提到、或讨论技能名称本身，都不触发。
- 门禁只管入口：已显式启动的同一流程内，用户回答提问或说“继续”仍按本流程接收反馈与恢复，不要求每轮重复点名，也不触发其他技能。
- 本次核查只代表核实并报告状态，不构成新的提交、合并、推送、发布、删除或版本升级授权，也不越过用户验收门禁；这些动作仍由用户另行决定。

## 四问范围

- 实现：用户布置的任务目标是什么，当前分支与工作区的实际改动（diff、文件内容、功能行为）是否覆盖它。目标不明确时先向用户确认范围，不自行脑补验收口径。
- 测试：本次改动有没有对应测试的真实证据——实际执行的命令、退出码与关键输出。没有证据就是未测试，不把“应该能过”当结论。
- 合并：改动现在落在哪个分支或工作区，是否已并入它该去的位置。以当前分支、提交记录与远端状态核实；分支没有未提交改动只说明工作区干净，不等于已合并；目标分支或目标位置不明确时问用户，不擅自推断。
- 尾巴：遗漏的清单项、临时改动、未决授权、遗留文件与后续待办。对照任务原要求逐条核对，不凭印象说“都做完了”。

## 证据规则

- 只认当前可复核的证据：实际命令与输出、文件当前内容、git 状态与提交记录。之前的口头宣称、会话早前的总结或记忆里的结论只当线索，引用前必须当场重新取证。
- 每问给一个状态：已证实（附证据）、未证实（说明缺什么证据）、不适用（说明为何不适用）。测试一问额外区分未测试与失败；失败写明命令与实际输出要点，不掩盖、不修饰。
- 证据不足时不填平：不替用户想象已经做过，不假设会通过，也不为凑结论降低证据标准。

## 授权边界

- 原任务已授权范围内必要的收尾验证可以做：只读检查、运行测试与构建、查看状态与日志；由此产生的缓存、日志等副产物不算修改产品。
- 涉及行为修改、新范围或新增文件的动作按现行权限处理：已有授权的照常，未授权的不做，列入未决事项交给用户决定；核查过程不借“收尾”扩大范围。
- 不提交、不合并、不推送、不发布、不删除文件、不改 `template_version` 等升级字段；发现这些动作待办时如实列出，等用户决定。

## 输出

- 简洁输出四项状态：实现、测试、合并、尾巴，逐项给结论与对应证据（命令、路径、分支名、提交号等可复核位置），最后列未决事项。
- 不空泛保证：没有证据的项写未证实并说明缺口，不使用“应该没问题”“都弄好了”这类无证据结论。

## 边界

- 不自动调用其他技能；发现需要逐点用户验收、文档一致性核验或记忆记录时，指出对应技能名称（如 ph-intent-verify、ph-docs-sync），由用户点名后再做。
- 逐点用户验收属于 ph-intent-verify：本技能的核查结论是事实陈述，不冒充用户验收结果。

## 完成标准

- 四项都有当前证据支撑的状态与结论，口头宣称没有被当作证据直接采信；未测试、失败与不适用已按实际区分。
- 分支状态与合并状态分开陈述，“工作区干净”没有被当成“已合并”，目标分支没有被擅自推断，不明确处已问用户。
- 核查未做任何提交、合并、推送、发布、删除或版本字段改动，未越过用户验收门禁；未决事项逐条列出，等待用户决定。
