# PH 开发共同约定

每个 PH 开发阶段开始时读取本约定。这里定义共同边界，不定义自动串联。面向用户的产物默认使用简体中文，项目或用户指定其他语言时遵从其要求。

## 权威来源与范围

读取项目 `.agents/AGENTS.md`、`.agents/project-harness/constitution.md` 及符合当前使用时机的约束文档。规划、实现、验证和归档时，读取 `.agents/project-harness/constraints/测试规范/` 下的门禁、用例、稳定性规范，再读取相关前后端的构建、自测规范。现行门禁不是可选项。缺文件或未填写的规则应报告为缺口，不能据此免除测试。

只执行用户明确点名要求使用的技能。名称提及、普通任务描述和下一步建议不是调用授权。明确启动阶段后的反馈与继续不要求反复点名。不自动调用其他技能。批准设计不代表授权实现、创建 worktree、提交、合并、发布或清理。必要决定使用宿主实际问答工具，正式审批使用专门审批通道。秘密不得通过聊天或普通问答收集。

先从代码和现行文档核实事实。仅向用户询问影响意图、范围、验收、兼容或授权的决定。保留已有答案和历史；未决时停止依赖该决定的动作，无关且已授权的调查可以继续。

## 功能身份与产物

活动记录位于 `.agents/project-harness/specs/<feature>/`。优先使用明确指定的功能路径；否则检查当前工作区分配和现有记录，多候选无法消歧时询问。不得默选最近修改的需求，不把全局共享指针用作并行任务协调机制。

| 产物 | 职责 |
| --- | --- |
| requirement.md | 目标、用户、范围、非目标、约束与用户成果验收目标 |
| design.md | 产品行为、交互及技术方案 |
| review.md | 设计发现、决定与受审来源状态 |
| tasks.md | 实现及修复任务、顺序、必要单元测试 |
| verify-plan.md | 智能体成果自测、预期结果及用例库落点 |
| acceptance.md | 已准备好的用户体验与成果确认指引 |
| verification.md | 实际执行证据、失败、用户反馈与当前结论 |
| change.md | 小改动的需求与最小设计，替代单独需求和设计文档 |

可执行脚本位于项目根相对路径 `.agents/scripts/ph_sdd.py`、`.agents/scripts/ph_human.py`；`project-harness/runtime/` 存放模板，不是这些脚本的位置。具体机械操作接口以 `python3 .agents/scripts/ph_sdd.py --help` 及子命令帮助为准。报告缺少工具前，先核实这里声明的路径。脚本辅助路径、结构和状态，不证明语义正确或用户真实同意。不得手改机器元数据绕过失败检查。

处理已有需求时遵守其产物映射。旧 `spec.md`、`plan.md` 可分别作为需求和设计来源；原编号、问答、附件、证据保留。不为更名重写历史需求。新的门禁需要实际核验，不能由旧勾选状态推定。小改动可以简写章节，但使用相同任务、验证和授权语义。不创建空的可选文档。

需求、验收、任务和发现使用稳定编号，保留旧编号。任务关联需求或设计依据，检查关联预期成果。勾选只是进度，不是运行证明。记录来源变化，使既有审查或验证能够被识别为需要重验。

## 证据与责任

记录实际命令或操作、时间、含未提交修改的代码状态、相关配置和环境、结果与证据位置。区分通过、失败、未执行和有依据不适用。缺测试不是不适用，读代码不是运行测试。新结果替代旧结果时保留历史。

相关代码、依赖、配置、环境、需求或设计变化后，重新判断证据有效性。只复用仍适用于当前状态的证据。指纹是漂移提示，不证明环境等价。不能把不明原因失败后的重跑成功直接当稳定通过，应遵守稳定性规范。

智能体负责单元测试、集成检查、回归、环境准备和技术排障。用户验收可用成果，不承担第二套技术测试。必要智能体检查通过后才邀请用户验收，提供可用入口、准备好的数据、代表性业务路径和有价值的预期结果。不让用户检查本应由智能体完成的日志、SQL、状态码或异常路径。

沉默、取消和环境不可达不是同意，应记等待或阻塞。内部修改没有合理的用户操作场景时，说明边界并展示交付证据，不编造人工操作，也不声称用户已通过验收。

## 并行开发

worktree 是可选执行环境。`ph-worktree-enter`、`ph-worktree-exit` 是独立且必须点名的技能。实现或归档需求不自动调用它们，也不授权其副作用。

委派前分配任务编号、文件归属、依赖、预期产出和验证责任。独立执行者可在登记的 worktree 中工作；共享文件、锁文件、生成物、端口、数据库和外部服务须单一负责人或串行访问。worktree 隔离文件，不隔离外部资源。

执行者维护自己的任务结果和证据，协调者更新共享任务清单、索引和集成结论。一个任务分支完成不代表整个需求完成。通过独立授权的退出操作集成，再验证组合后的成果。合并前证据不证明合并后状态。

## 伴读与交接

新增或实质更新受支持的权威产物时，读取[伴读写作规范](../../ph-human/references/human-writing.md)，撰写解释伴读并经 `ph_human.py` 发布，不调用 ph-human。只解释真实来源。发布冲突应报告，不覆盖用户改动。伴读不是验收依据，不替代证据。不刷新无关伴读，不编造缺源快照。

收尾报告修改的产物、实际检查、未解决项及适合的下一技能名称，只建议不调用。新会话应能从文件与当前代码恢复工作；清空或压缩对话是可选操作，不是正确性门禁。
