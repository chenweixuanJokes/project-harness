# ph-memory-ask

只读检索本仓库记忆库，回答“以前记过什么”。不创建、不修改、不移动、不删除任何记忆文件。

**调用门禁**：仅当用户当轮明确点名本技能（如「用 ph-memory-ask 查记忆」）并要求使用时才执行。用户只说“查一下记忆”“你还记得吗”、上下文提及、或讨论技能名称本身，都不触发。

## 何时用 / 何时不用

使用：回忆、盘点、追溯历史记录；问记忆里有没有某结论。

不用：

- “记住 X” → `ph-memory-capture`
- 归档 / 沉淀 → `ph-memory-archive`
- 普通知识问答、只讨论当前对话、不涉及既有记忆
- 用户要改规范或 Wiki——先核验当前文档，不在本技能里改

## 路径定位

1. 从当前工作目录向上找同时存在 `.agents/ph.json` 与 `.agents/AGENTS.md` 的仓库根。找不到则停止。
2. 只搜索：

   - `<repo>/.agents/memory/structured/`
   - `<repo>/.agents/memory/temporary/`
   - `<repo>/.agents/memory/archive/`（仅当用户要原话、前两层不足或需要核冲突）
3. 读取 `memory/README.md` 了解效力。不要使用 Obsidian CLI 或用户绝对路径。

## 安全边界

- 不逐字回显疑似秘密（密码、令牌、Cookie、私钥、完整连接串）。只说明“某条记忆提到某类凭证”，并给出不含秘密的路径。
- 个人信息按问题所需最小化披露。
- 调用本技能不等于授权修改、部署、删除或对外发送。

## 工作流

1. **确认问题**：提取主题、别名、时间线索，以及用户是在回忆，还是准备据此行动。
2. **检索**：按文件名、`topics`、标题、正文关键词搜索。前两层都要看，不能因结构化文档命中就忽略更新的临时记忆。先搜索再读少量相关全文，不要把整个记忆库灌进上下文。
3. **阅读**：读命中章节的完整上下文。结合 `created` / `updated` / `provenance` / `confidence` / `review_after` / `supersedes` 判断时效。结构化文档与其归档原件是同一来源链，不算两份独立证据。
4. **评估**：

   - 记忆明确记录
   - 根据多条归纳（须标明归纳）
   - 记忆中未找到（不补模型常识，不自动联网，不写回新记忆）
   - 多条冲突时并列日期与原文，不擅自裁定当前真相
5. **回答**：先给结论，再给可核对的仓库相对路径。影响判断时注明“这是历史记忆，仅供参考，当前有效性尚未验证”。`review_after` 已过或 `status` 为 `superseded` 时明确提示。

## 验证与执行门禁

只回忆：到“参考答案 + 来源 + 时效”为止。

若用户要据此做当前决定或操作，把记忆当待验证假设，按此顺序核验：

1. 当轮用户指令与 `.agents/AGENTS.md`
2. `docs/约束规范/`、当前代码、配置、接口或运行时事实
3. 仍不足且确有必要时查该主题的权威资料
4. 仍无法确认则停止并询问。对用户说明记忆和当前代码对不上，问“按记忆做之前，你要怎么处理”，问法见 [对用户提问](../../../docs/约束规范/工程规范/对用户提问.md) 的“把问题写成可回答的决定”。

核验与记忆不一致时，以当前权威事实为准，并指出相关记忆可能过期。未完成核验不得把记忆转成操作步骤。权限、安全、部署、删除、覆盖、对外发送、凭据使用等即记忆写明也不能只凭记忆执行。

## 完成标准

- 未改动记忆库或任何其它文件。
- 回答区分“记忆所述”与“当前已核验”。
- 引用使用仓库相对路径；冲突已并列。
- 未回显秘密。需要行动时给出核验结果或待确认项，而不是直接执行。
