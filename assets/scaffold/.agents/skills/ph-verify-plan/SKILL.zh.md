# ph-verify-plan 中文对照

仅当用户明确点名 ph-verify-plan 并要求使用时执行；普通描述、名称提及和下一步建议不触发。明确启动后的继续不要求重复点名，不自动调用其他技能。

# 准备验证与验收

读取[开发共同约定](../ph-require/references/process.zh.md)。本技能写计划，不写执行结果。前置是已审设计和可用任务计划。同时读原始需求，不能因任务遗漏而让验收也遗漏。

## 智能体自测计划

参考 `runtime/templates/sdd/verify-plan-template.md` 写 verify-plan.md。每个稳定检查编号记录：

- 关联需求/成果及所检查风险。
- 真实入口、环境、数据、资源负责人、准备与清理。
- 具体操作或拟用命令、断言与有价值的预期结果。
- 待收集证据及满足的项目门禁。
- 复用的用例编号，或拟新增/更新用例及长期落点。

覆盖主流程、集成、重要异常、权限、受影响回归和适用的视觉/输出质量。按宿主工具能力与委派规则选择手段；浏览器和视觉检查不自动变成人工任务。

单测属于实现任务，不在此重复展开，但需引用其证据及项目要求的全量重跑。缺少单测或测试设施记为任务计划缺口，不能据此免测。

可复用冒烟用例进入相关前后端 PH 用例库，单元与接口测试代码留在项目测试目录。拟用命令是未执行建议，不是长期命令配置或通过证据。不能把凭证、个人绝对路径、临时端口作为永久用例要求。

## 用户成果验收指引

参考 `runtime/templates/sdd/acceptance-template.md` 写 acceptance.md，说明智能体会准备什么、用户从哪里体验、代表性业务路径及需要判断的有价值结果。流程简短，但不删除重要验收目标。

例如筛选订单导出：智能体检查权限、空结果、文件内容和回归；用户对准备好的代表性筛选结果导出一次，判断文件是否满足实际对账工作。不让用户再测异常、不查日志、不对照数据库行。

区分成果目标与测试断言。用户判断适用性、表达和使用流程，智能体负责技术正确性。内部改动没有合理手动场景时，说明原因与替代展示证据，不据此编造用户批准。

## 核对与交接

每项需求应有智能体检查、用户成果标准或有理由的替代。需求无法验证或缺准备任务时，报告具体缺口并返回对应设计/任务阶段，不暗改范围。不标记任何运行检查已通过。

审阅后记录计划 reviewed，发布支持的伴读，建议 ph-implement。worktree 进入仍需独立点名。后续 ph-verify 执行检查，并在智能体自测通过后准备实际用户入口。
