# ph-intent-impl

准备充分后交接，而不是在普通模式先写一份完整计划、切换后再写一遍。允许在普通模式启动；正式实施计划交给宿主原生计划模式。调用本 Skill 是启动推进：把仍在待办的意图迁入实施。实施目录覆盖准备、规划、开发、验收，但不表示计划已获批，也不授予业务代码写入、提交或发布。本 Skill 不自动写业务代码、不自动完成或发布。

## 入口与权限

1. 向上定位同时存在 `.agents/ph.json` 和 `.agents/AGENTS.md` 的 PH 仓库。缺失时停止，不自动安装 PH。
2. 读取当前项目约束、仓库根下 `docs/约束规范/工程规范/意图与访谈.md`、意图及纪要模板。定位唯一目标意图，先检索再询问真正的目标、类型或状态歧义；有真歧义则不可迁移。对用户只问“这次要推进哪一条”，问法见 [对用户提问](../../../docs/约束规范/工程规范/对用户提问.md) 第 3 节。
3. 遵守宿主当前模式和写权限。已经在计划模式时不退出再重进；可写则仍须先完成下文启动迁移（若尚未进入实施），只读则不迁移。意图虽未充分澄清，也不能借补访越过只读限制。
4. 模式依据只能来自当前宿主明确的系统信号或原生工具返回。存在计划文件、用户要求规划、自设环境变量或 `--plan-mode` 参数都不是证据。无法确认权限时停止受限写入，不能默认可写。
5. 读写范围为当前意图、相关纪要、必要索引与引用；无业务代码写入权限。检查仓库内路径，拒绝软链/junction 重定向；所有持久化内容先去密。

## 分支与工作区

默认在当前所在分支和当前工作区推进，不新建或切换分支，也不创建 worktree。调用本 Skill、启动意图或批准实施计划，都不代表授权改变分支或创建隔离工作区；不要因为当前分支是 main/master 或任务涉及开发而自动执行这些操作。只有用户明确要求时，才按要求处理分支或调用 `ph-worktree-enter`。交接给计划模式时保留这一边界，不把创建分支或 worktree 加为默认前置步骤。

## 启动目录：可写则先迁移

对**唯一、可写、无真歧义**的目标，在调研、补访、写交接或切换计划模式之前完成启动迁移并核实。不要把目标/类型/状态的真正歧义当成可迁移。

| 来源 | 目标 |
| --- | --- |
| `待办/新特性` | `实施/新特性` |
| `待办/问题记录` | `实施/问题记录` |

`ph-intent-new` 补充不自动迁。已废弃、目标不唯一、类型或状态不清、只读、目标同名冲突均不迁移；已废弃只说明冲突，不擅自重开。已交付意图同样位于实施，按幂等继续处理，不视为未启动。

1. 读目标，确认仓库内真实路径。`docs/意图/实施/<分类>/<原文件名>` 已被不同文件占用时停止，不覆盖、不改编号抢占。
2. 已在对应 `实施/` 目录：视为已启动，幂等继续；不重复首次启动记录，不搬回待办。文件已在实施但 `status_dir`、链接或 README 不完整时，先修这些项，仍不追加第二条启动记录。
3. 需要移动时：在「记录」追加日期、来源目录、目标目录和启动依据（用户调用本 Skill），再普通文件移动，保留 `intent_id`、正文历史和纪要位置。纪要不移动。
4. 将 `status_dir` 改为 `实施/新特性` 或 `实施/问题记录`，更新日期；修复当前有效入站/出站相对链接、frontmatter 路径和沿途 README。同深度移动时纪要正文链接通常仍为 `../../访谈纪要/<iv>.md`，仍须逐个从实际父目录解析确认。
5. **核实完整**后才能调研、补访、写交接或切换计划模式：文件已在实施对应分类、`status_dir` 一致、有效入出链可解析、沿途 README 覆盖新位置且不再把该文件留在来源索引。
6. 切换失败、被拒绝、无法确认或暂停后，意图仍留实施，不退回待办。无需再移动或改名来表达切换成功；实施只表示已启动推进，不表示计划获批。

**只读**：不移动或修复文件。可继续原生只读规划，按实际位置报告：仍在待办时，说明尚未迁入实施，并在审批计划中列出「恢复可写后、在业务实施前完成迁移并核实」；已在实施且完整时直接继续，不报告待迁移。存在待修复的状态、链接或索引时同样列为恢复可写后的前置项，不虚报已修复。

**迁移途中失败**：列出已完成/未完成步骤和文件实际位置，停止后续切换；不宣称原子移动，不用强制覆盖或自动回滚消现场。重试先修复未完成项与外部修改，不重复追加首次启动记录。

## 普通模式：准备交接

### 1. 研究意图与当前事实

- 读取意图、`interviews` 和旧 `related` 中的相关纪要、项目约束及受影响代码、配置、测试。检查旧结论是否已因代码或需求变化失效。
- 不以 `clarification_status: clear` 或“已经访谈过”代替实际核对；也不因模板字段缺失就否定历史中已经明确的答案。
- 已废弃意图不直接按新需求规划；实施中已交付的意图有新需求时说明范围冲突，不擅自重开、迁移或自动另建意图。
- 区分用户决策缺口和可在计划模式继续研究的技术问题。不要求用户替 Agent 做代码调研。

### 2. 必要时补访并保存

- 目标、范围或验收仍不明确，或当前证据产生新的关键取舍时，按共用访谈规则补访。
- 每轮先查，说明提问原因，一次一个决策，推荐选项置首并给理由，允许自由回答；得到实际回答后及时保存，再决定下一问。
- 需要补访时创建 purpose 为 `plan` 的新纪要，由意图 `interviews` 引用；保留旧纪要原文，新结论注明取代或修正了什么。
- 本次没有补访则直接引用已有证据，不为凑数量创建虚假问答。若实际执行了澄清性讨论，必须记录过程，不能只留下结论。
- 关键用户决定仍缺失时停在澄清阶段，记录待继续问题，不切换后假装缺口已解决。用户中断时保存已回答内容及 `paused` 状态；已启动的目录仍留实施。

### 3. 写规划输入，不写完整计划

在意图的“计划交接”节整理：

- 意图编号及当前路径、目标、范围和非目标；
- 关键约束与验收标准；
- 已明确的用户决定与纪要引用；
- 相关代码、配置、测试的路径和已核实事实；
- 风险、待研究的技术问题及证据限制。

这里不提前制定最终架构、逐步实现任务或完整实施计划。更新日期、必要索引和链接，核实写入成功。交接材料是当前快照，历史问答仍保留在纪要中。

### 4. 驱动会话切换

- 查看宿主实际暴露的原生计划模式能力；例如本会话确有 `EnterPlanMode` 时才使用，不能假定所有 Agent 有同名工具或虚构命令。
- 调用原生切换能力，需要用户批准则遵守宿主流程，等待并检查实际结果。
- 宿主明确确认进入计划模式后，继续下节的正式规划；只有“请求已发出”不代表切换成功。
- **没有切换能力**：给出已保存的意图/纪要/交接位置，说明“目标和材料已经整理好了。这个会话不能自动切到「先出方案、先不改代码」。请你在客户端里手动切过去，然后说一声继续。” 宿主按钮若就叫计划模式，可以沿用这个词，但仍要补上这句解释。然后停止；不继续输出完整计划。已启动则目录留实施。
- **被拒绝、失败或无法确认**：如实说明状态并停止。不要反复重试被拒绝的调用，不通过另起会话或自称模式切换绕过限制。已启动则目录留实施。

## 原生计划阶段

1. 确认宿主当前处于计划模式，读取目标意图和交接材料。已在该模式调用本 Skill 时，可直接做同样的只读调研，无需重复生成交接文件；可写且尚未进入实施时，仍须先完成启动迁移并核实。
2. 有新缺口再按同样的一问一答机制补访。没有项目写权限时将实际问答保留在会话或宿主明确允许的计划产物，列为“待归档、未写入项目”，保留意图编号及引用目标；不得改 docs 或虚报纪要已保存。
3. 正式研究可复用实现和影响范围，制定包含步骤、修改位置、测试与完成标准、风险、必要迁移/兼容安排的实施计划。只读规划按实际目录与完整性报告；仅有待迁移或待修复项时，将恢复可写后的处理列为业务实施前的前置交付项。目标和验收不明确时继续澄清，不用技术方案掩盖需求缺口。
4. 按宿主原生方式交付计划并请求审批，遵守该工具的实际语义。请求规划不意味着计划获批，也不意味着已授权业务实现、提交或发布。
5. 返回实际计划产物位置或宿主提供的计划内容，不编造文件路径。待归档纪要及引用作为明确交付项保留；不为了保存这些内容自行退出只读模式，不自动写入厂商未授权的路径。

## 完成状态

- **待澄清**：关键用户决定缺失，准备未完成；若已启动则目录仍在实施。
- **待手动切换**：交接准备已保存，但无工具或切换失败；正式计划尚未制定。已启动则留实施。
- **计划待审批**：真实计划模式内已交付实施计划，仍不代表获批或实现。
- **未迁移（只读）**：目标仍在待办时，说明尚未迁入实施；已在实施的意图不报告为未启动。

分别报告真实状态、目录实际位置及已保存/未保存的内容；不把“整理了交接材料”叫作已完成实施计划，不把“已迁入实施”叫作计划获批或已实现，不执行代码、测试部署、提交或发布来跨过规划边界。
