# ph-archive 中文对照

仅当用户明确点名 ph-archive 并要求使用时执行；普通描述、名称提及和下一步建议不触发。明确启动后的继续不要求重复点名，不自动调用其他技能。归档不授权提交、合并、退出 worktree 或清理。

# 归档需求并沉淀资料

读取[开发共同约定](../ph-require/references/process.zh.md)、项目文档治理及相关测试用例/门禁规则。这里是功能归档，不是 ph-memory-archive，也不是退出工作区。

## 1. 核实完成与位置

读取当前需求/change、设计/审查、任务、验证计划、实际证据和用户成果决定，检查仓库及工作区分配。确认必要工作完成、智能体证据有效、用户已验收或有明确且有依据的适用性决定，没有阻断发现。

同组工作尚未集成时，执行者分支不能归档整项需求。必要时读取 worktree 运行时只读 doctor/分组信息。任务分支上的完整已验收功能不同于合入交付：前者可明确标注未合入并保存快照，不得宣称源分支已通过验证。

证据过期、用户未答或工作未完成时报告具体阻断和适合的阶段。不为保存历史强标完成。可以保全未完成材料，但不能标作完成需求。

## 2. 沉淀现行项目事实

对照实际成果和已有项目文档，只更新受影响事实：功能地图、产品行为、架构、数据契约、接口、使用/构建及运维说明。优先更新已有权威位置，不造重复文档。PH 外业务文档仍属项目，只修改与本次已授权需求直接相关的文档。

PH 资料维护目录 README 索引及真实 owner/status/last_verified/verified_against/refresh_trigger。负责人未知保持 unknown，局部核验不冒充整页核验。保留无关定制、链接和仍有效正文。

规则不同于事实，不把实现选择或记忆建议自动升为约束。只有已授权、明确采纳的规则变更可写入 constraints，并更新宪法导航；重大架构决定按 ADR 规则记录。未决规范变更阻断该项，不能降低门禁。不自动调用记忆技能或因归档产生记忆写入。

## 3. 沉淀可复用测试用例

读取 verify-plan 中拟定用例落点及真实已测实现，复用稳定编号、去重，关联需求、脚本与证据。

- 单元/接口自动化测试保留项目真实测试目录；不能拖到归档才实现，也不由归档替代实现。
- 已验证可复用冒烟场景按既有模板登记或更新对应前后端 PH 用例库，一例一文件。
- 保留前置、安全数据准备、操作、断言、清理、真实脚本位置和证据。不把临时命令、个人路径、临时端口或秘密变成长效配置。
- 失败/未执行候选如实记录，不能出现在通过的沉淀报告。必需用例未实现或失败时返回可追踪任务，不能宣称归档完成。
- 用户代表性成果路径不是第二套技术测试，不能原样复制为强制测试库。

文档/用例变更后执行适用检查，新增或修改可运行用例须按门禁实测。快照定版前重新判断被这些改动影响的证据。

## 4. 保存历史

在活动功能记录写归档摘要：交付范围、来源/证据状态、用户结论、文档/用例落点、已知限制、真实合入/发布状态。不需要更新的部分说明原因，不造填充文档。

通过随包 ph_sdd.py archive 先预检再 apply，保存带校验清单的功能快照和索引。保留活动功能稳定路径及引用，不搬走造成断链，不以摘要替代源历史。同状态重复归档应幂等。核对快照清单与活动链接，机械或语义失败分别报告。

## 5. worktree 交接

不调用 ph-worktree-exit 或其 apply 命令。在工作区内归档时，明确代码、文档、用例和快照仍位于该分支，后续授权交付应一起带回。合并后归档则使用真实集成状态和合并后证据。

独立退出技能负责提交/合并、合并后检查及另行确认的清理，归档不授权这些操作。清理前证据须保存在即将消失的环境之外或受跟踪交付材料内；指向将删除任务目录的链接不是持久证据。

## 完成标准

需求历史可恢复，受影响项目事实和可复用冒烟用例反映已验证实态，引用有效，验证/归档/集成/发布状态分别报告。没有越权 Git、记忆或外部动作。
