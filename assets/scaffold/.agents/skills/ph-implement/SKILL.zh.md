# ph-implement 中文对照

仅当用户明确点名 ph-implement 并要求使用时执行；普通描述、名称提及和下一步建议不触发。明确启动后的继续不要求重复点名，不自动调用其他技能。

# 执行准备好的任务

读取[开发共同约定](../ph-require/references/process.zh.md)。本阶段执行任务，不替代成果级自检或用户验收。

## 编辑前

1. 明确仓库、需求及可选的已登记 worktree/任务分配。读取 requirement/change、适用设计、审查、tasks、verify-plan、acceptance。运行只读 status/check，调查陈旧来源。空计划、缺计划或未解决设计阻断应停止相关实施。
2. 读取构建、自测、单元、冒烟、回归和稳定性规则。检查当前改动并保护用户编辑。verify-plan 中待执行检查是实现前的正常状态，不能当成需求质量评审失败。
3. 确认任务授权范围。默认当前分支，另有明确授权才改变。不调用 ph-worktree-enter、ph-worktree-exit、ph-verify、ph-archive。不自动提交、合并、推送、部署或做付费/外部操作。

## 执行

4. 按依赖顺序工作。每项先看实际源码，做最小适当修改并编写/更新必要单测。Bug 必须有复现证据才宣称修复。运行任务检查及项目要求的单测门禁；无关失败如实报告，不暗中修复或排除。
5. 宿主支持时只委派可独立验收任务，明确文件归属、依赖输入、任务编号和测试责任。使用已经授权登记的 worktree；共享文件、锁文件、生成物和外部资源唯一写入或串行。不能为了方便并行擅自新建工作区。
6. 执行者返回限定范围结果、改动文件、实际检查、证据和未决项，不共同改写共享任务表与项目索引。协调者检查并整合结果，不能仅凭执行者自述确认需求完成。任务分支不是集成后的最终成果。
7. 事实使设计失效时停止相关工作，说明差异，不暗改验收、不替用户决定产品、不猜接口继续。授权实现内的局部问题可以修复并重跑任务检查。
8. 真实满足完成条件才更新任务进度，保留编号和历史证据。在 verification.md 或分配的执行者证据文件记录实际命令、代码/环境状态、结果和证据。未完成/阻塞如实标记，勾选不能代替运行证据。
9. 按任务同步相关实现文档与测试代码，不把自动化测试编写拖到归档。可复用冒烟候选保留链接，待验证后沉淀；未执行用例不宣称通过。

## 交接

核对任务与证据，刷新支持的伴读，分别报告实现/单测结果、成果级自检、用户验收和合入状态。分配工作就绪时建议 ph-verify。并行部分仍需集成时，说明独立授权的 worktree-exit 及集成验证尚未完成。不因任务全勾就宣称需求已交付。
