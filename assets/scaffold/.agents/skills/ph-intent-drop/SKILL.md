# ph-intent-drop

保留用户为什么不再实现的证据，而不是把文件挪走就算结束。用户已明确说明原因时直接复用；不知道原因就询问，不能替用户编造。此 Skill 只改变意图文档生命周期。

**调用门禁**：仅当用户当轮明确点名本技能（如「用 ph-intent-drop 废弃 INT-…」）并要求使用时才执行。用户只说“废弃这个意图”“这个需求不做了”、上下文提及、或讨论技能名称本身，都不触发。

## 入口与边界

1. 向上定位同时存在 `.agents/ph.json` 与 `.agents/AGENTS.md` 的 PH 仓库，缺失则停止，不自动初始化。
2. 读取项目约束、仓库根下 `docs/约束规范/工程规范/意图与访谈.md`、`docs/意图/_模板.md` 和纪要模板。
3. 只改目标意图、本次纪要、必要索引及相关链接；不删除历史，不修改业务代码、Wiki 或记忆，不取消外部任务、不清理分支/worktree、不连带废弃依赖意图。
4. 遵守宿主权限。只读模式可以澄清并给出待归档决定，但不得移动或写 docs，不能声称已废弃。
5. 写入和移动前读目标，检查仓库内真实路径，拒绝软链/junction 重定向；内容先去密，不将凭证或个人敏感信息写进原因、问答或证据。

## 工作流

### 1. 确认目标及现状

- 根据用户给出的编号、路径或描述，检索并读取意图、历史纪要及关联材料。先用证据消除歧义，仍有多个目标时一次只问选择哪一个。对用户开口遵守 [对用户提问](../../../docs/约束规范/工程规范/对用户提问.md) 的“把问题写成可回答的决定”，不要问内部目录名或状态字段。
- 已废弃时报告已有日期与原因，重复调用不重复移动；用户提出补充原因时只按明确要求追加新记录，不重写原决定。
- 实施中已交付的意图被要求废弃时，先确认这是下线或撤回已交付能力，而不是放弃未开始的工作；对用户问“你是要下线已经上线的能力，还是只放弃还没做的后续”，并说明下线不会自动改代码。不擅自变更状态。
- 检查相关意图和已有实现可能受到的影响，只记录事实，不把这些影响当成自动回滚或取消授权。

### 2. 明确原因与决定

- 用户已给出明确废弃决定和真实原因，例如“上游功能已经下线，这个需求不再存在”，直接记录来源，不再机械问为什么。
- “先不做”“优先级低”若尚不能区分延期与废弃，只问这个会改变处理方式的分歧，例如：“你说先不做，我还分不清是暂时放下还是彻底不做。选哪一种？” 用户选择延期则保持原状态（待办或实施），不能擅自移入已废弃。
- 原因未知时先查现有讨论和纪要，再提出一个必要问题，说明为何需知道原因及其对历史追溯的影响，给出有依据的推荐和自由回答入口。对用户问“为什么不再做”，推荐“我先不放弃，等你补原因”。
- 不默认推荐价值不足、预算不足、技术不可行等未经确认的动机；证据不足时推荐“补充真实原因后再废弃”这种处理方式（对用户用上一句白话）。选择了处理方式但没有给原因，不算已经回答为什么。
- 每轮保存实际问题、提问原因、证据、选项与推荐理由、用户回答和结论，再问下一轮。需要时建立 purpose 为 `abandon` 的纪要并由意图引用。
- 零新增问题时仍记录本次废弃决定的原始来源和理由；不编造访谈轮次。
- 原因缺失、决定未明确、用户中断时保存已回答内容及未决问题，纪要标 `paused`，**不移动意图**。目标本身已清晰时不为废弃访谈的中断错误地推翻目标澄清状态。

### 3. 保存决定，再安全移动

以下均满足后才执行：用户已明确要求废弃、原因明确、目标唯一、路径安全、具备写权限、目标文件名无冲突。已有明确授权不重复索取同一次移动批准；单纯讨论“要不要废弃”不算授权。不要求先把待办迁入实施。

1. 检索受影响的当前入站/出站引用，确认 `docs/意图/已废弃/<原文件名>` 不会覆盖任何文件；冲突时停止，不使用强制参数解决。
2. 保存本次纪要，意图引用纪要；在意图历史中追加日期、废弃原因和来源、影响、确有依据的替代意图。用户没给替代项就不编造。
3. 执行普通文件移动，保留 `intent_id`、原文历史和纪要位置。移动不删除纪要、不删除其他文件、不改 Git 分支。
4. 将 `status_dir` 改为 `已废弃`，更新日期；修复正文中的有效相对链接、其他文件指向本意图的当前链接、必要 frontmatter 路径和沿途 README。
5. 不无差别替换旧问答原话或代码块中的历史路径。检查新的意图位置、纪要关联、索引和当前有效链接。例如从 `待办/新特性/` 或 `实施/新特性/` 移到 `已废弃/` 后，纪要的正文链接应从 `../../访谈纪要/<iv>.md` 调整为 `../访谈纪要/<iv>.md`；frontmatter 中的仓库根相对纪要路径不变。逐个从实际文档父目录解析并确认目标存在，断链未修复前不报告完成。

中途失败时列出已经完成/尚未完成的步骤、实际文件位置和恢复所需信息；不宣称原子移动，不通过强制覆盖或自动回滚消除现场。重试先检查实际状态和外部修改，避免重复追加决定。

## 交付

返回意图原位置与新位置、真实原因及纪要、必要的关联影响。说明业务代码和外部事项未改变。延期、原因待补、只读待执行、已废弃是不同结果；只有实际完成移动、状态和引用检查后才能报告“已废弃”。
