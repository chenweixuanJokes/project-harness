# 文档治理

Last verified: <填写：YYYY-MM-DD>

> 管文档怎么放、怎么索引、怎么过期，不管各域的业务事实。业务事实分别写在约束专文、意图正文和 Wiki 页。

## 1. 三域

| 域 | 目录 | 效力 |
| --- | --- | --- |
| 约束规范 | `docs/约束规范/` | 强制。与其它文档冲突时以约束为准 |
| 意图 | `docs/意图/` | 过程记录。状态靠目录表达，不靠改标题假装完成 |
| Wiki | `docs/项目Wiki/` | 现行叙述。过期按 refresh trigger 重验，不把它当规范 |

记忆在 `.agents/memory/`，不属于 `docs/`，不能替代本文件或约束。

## 2. 目录与索引

- `docs/` 内目录名用中文（`约束规范`、`意图`、`项目Wiki` 及其子目录）。文件名可用中文或英文，同一目录内保持一致。
- 最终 `docs/` 根只允许 `README.md` 与 `约束规范/`、`意图/`、`项目Wiki/`。接入前的旧文档目录（如 `docs/specs/`、`docs/domains/`、`docs/plans/`）及其顶层正文必须按内容归并，不留旧目录、空壳或软链。PH 固定入口的摘要 + 深链指向归并后的正文，被引用旧规范保持效力。迁移细则见 [初始化与文档补全.md](./初始化与文档补全.md) §1.1。新建目录仍用中文命名。
- **每个文档目录必须有一个 `README.md`**。README 只做索引和一句话定位，不复制正文规则。该目录下的每篇直接文档和每个子目录入口都必须列入 README；漏索引即失败。
- 新增 / 移动 / 重命名文档后，同步所在目录与各级上级 README，并检查 `.agents/AGENTS.md` 与其它文档的相对链接。
- Wiki 非 README、非模板页必须含 owner、status、last_verified、verified_against、refresh_trigger。模板占位允许空值或 `<填写>`，但不得谎报已经核验。
- 不为脑图或清单上的每个叶子预建空文档。同类约定写进一篇汇总规范，重复结构用模板表达；真正有内容时再拆专文并补索引。
- `.agents/init-report.md` 是初始化补全的实现记录，不属于 `docs/` 三域，也不替代任何规范、Wiki 正文或意图记录；约定见 [初始化与文档补全.md](./初始化与文档补全.md) §6。
- `.agents/archived/` 是初始化或文档归并前的原文快照，不是现行文档、不是记忆，也不进本域索引；约定见 [archived/README.md](../../../.agents/archived/README.md)。

## 3. 意图移动

- 每条意图有稳定 `intent_id`（见 [意图模板](../../意图/_模板.md)），移动文件时不改 id。
- 状态靠目录，不靠正文里的“状态”字段单独生效：

  | 状态 | 目录 |
  | --- | --- |
  | 待办的特性 | `docs/意图/待办/新特性/` |
  | 待办的缺陷 / 事故 | `docs/意图/待办/问题记录/` |
  | 实施中的特性 | `docs/意图/实施/新特性/` |
  | 实施中的缺陷 / 事故 | `docs/意图/实施/问题记录/` |
  | 已废弃 | `docs/意图/已废弃/` |

- `new` 新建入待办对应类型目录；补充已有意图保持其当前目录。`impl` 在可写时先把唯一目标迁入对应实施目录，再调研或切换计划模式；实施覆盖准备、规划、开发与验收，不等于计划获批或业务代码授权。`drop` 从待办或实施移入已废弃。交付的意图留在实施，在「记录」注明日期与验收证据；不设已完成目录，也不自动记录交付。
- 启动实施或废弃时**移动**意图文件，保留 `intent_id`，更新 `status_dir`、必要入站/出站链接和沿途 README，并在正文追加日期、原因和证据。不要复制一份到目标目录再留原件，不覆盖目标文件。
- `docs/意图/访谈纪要/` 是过程证据目录，不是意图生命周期状态。新纪要有独立 `interview_id`，通过 `intent_id` 关联意图，意图通过 `interviews` 引用纪要；纪要不随意图完成或废弃而移动。
- 澄清程度 `clarification_status` 与目录状态、计划审批分开。访谈录入、补访、废弃及旧纪要兼容规则以 [意图与访谈](./意图与访谈.md) 为准。

## 4. Wiki refresh trigger

每篇 Wiki 页顶部 frontmatter 必须含：

| 字段 | 含义 |
| --- | --- |
| `owner` | 谁对过期负责 |
| `status` | `draft` / `active` / `deprecated` |
| `last_verified` | 最近对照事实核对的日期，`YYYY-MM-DD` 或空 |
| `verified_against` | 核对时所依据的提交、标签或路径 |
| `refresh_trigger` | 何种变化发生后本页不得再当现行叙述，必须先重验 |

触发条件已发生、但 `last_verified` 早于该变化时：先重验或标明过期，再引用该页。发布前与重构合入前，至少按各页 `refresh_trigger` 扫一遍受影响 Wiki。

建议默认触发（可按页收窄）：

- 项目概述：目标用户、范围或成功标准变化
- 功能地图：用户可感知功能、路由或模块归属变化
- 开发指南：启动、构建、环境变量或依赖安装命令变化
- 领域页：该域模型、边界或持久化结构变化
- 架构页：模块划分、调用关系或技术选型变化

## 5. 与 AGENTS.md 的关系

`.agents/AGENTS.md` 只保留摘要和深链。长规则新增在本域专文，不在 AGENTS 里展开第二份。厂商入口是适配层副本，不在那些文件上改治理规则。

## 6. 文档同步检查与修复

由代理按本节在普通会话执行，覆盖 README、docs 配置说明、使用示例与 Wiki 现行叙述；本节是规则源。不设 `ph-wiki-sync` 或定时巡检任务；不因为“该检查了”就自动改 Wiki 或造记忆 / 意图。检查请求默认只读，用户明确要求同步修复才可写文件。

对照范围：

- **当前代码、配置、锁文件、CI、现行约束是全量事实源。** 当前工作区（含未提交改动）是事实；近 7 天提交只提供“可能过期”的变化线索（提交信息、路径、日期），用来优先点名要重验的页，**不**把核验范围限制在这 7 天，也**不**用 7 天无提交推断文档仍然正确。提交标题不能证明实现，找不到提交也不能证明不存在。
- 先读各页 `refresh_trigger`、`last_verified`、`verified_against`。触发已发生且核验日早于该变化，或正文与代码冲突：该页不得再当现行叙述。
- 约束规范规则不在同步范围，不从代码倒推改写（见 §7）。

修复门禁：

1. 只修可直接证实的不一致，保持原文档结构与术语风格；每处修改报告文件与依据，无修改时报告实际核对范围与证据。不把同步结果写进约束，除非用户明确要升格规则。
2. 五个字段必须写真实值；`owner` 未知填 `unknown`，不猜；局部核对不得谎称整页核实。
3. 命令若未执行，保持 `待核实`，见 [初始化与文档补全.md](./初始化与文档补全.md) §7。
4. 范围要扩到其它域或与定制冲突：停止受影响项。
5. `ph-init check` 通过不能代替本流程。

## 7. 纠正

按域处理。记忆纠正没有专属流程；文档同步检查与修复按 §6 由代理执行，但纠正与同步都不自动升格规则，也不因存在检查规则就自动执行。

| 对象 | 做法 | 禁止 |
| --- | --- | --- |
| Wiki | 对照当前事实改现行正文与五字段；过期原因可留在页内一句 | 不把建议写成已核验事实 |
| 约束 | 仅当用户确认规则变更；必要时先 ADR | 不从坏代码或过期 Wiki 倒推强制句 |
| 意图 / 纪要 | 新结论追加记录或新纪要，保留旧原话 | 不改历史答案顶替、不因纠正移动状态目录 |
| 记忆 | 新临时记忆或 structured supersede；archive 原件不改写、不删除 | 不把纠正结果自动升为规范或授权；秘密仍不得入库 |

纠正前先标生效状态（规范 / 事实 / 待采纳建议 / 待核实），定义见 [初始化与文档补全.md](./初始化与文档补全.md) §4。待核实内容可以纠正为“仍未知”，不能纠正成未核验的肯定句。

## 8. 问答门禁

回答仓库“现在怎样 / 必须怎样 / 以前记过什么”时：

1. 强制问题只引用 `docs/约束规范/` 与 `.agents/AGENTS.md`。
2. 现行事实引用经过当前代码复核的 Wiki；日期新不代表事实仍有效。过期时先只读取证，在回答中说明差异，不能借问答自动执行 §6 的写入修复。
3. 历史回忆检索 `.agents/memory/` 或直接查意图纪要，并标明参考性质。
4. `待采纳建议` 必须说“尚未生效”。`待核实` 必须说缺口，不当答案。
5. 问答本身不写文件、不造记忆 / 意图、不部署、不通知。用户要求改文档时再按纠正或补全流程授权。
